- [x] 1.16 The browser round trip under test, in `apps/e2e/src/sign-in.browser.spec.ts` against the Playwright fixtures. Three things it needed and now has: an issuer-registration path (`registry:registerIssuer`, internal — registering an issuer is an operator act, so it declares no capability), a page that is the human's client in `apps/centaur-server-reference/src/routes/sign-in/`, and a signed-in human, which costs one substituted verification step in the deployment's own provider (`substituted-provider-verification`, absent unless two environment variables configure it). It runs under Chromium by default and under all three engines from `pnpm e2e:browsers`, because what it turns on — a cookie carried on a top-level cross-origin navigation, and session storage surviving one — is where browsers differ.

  **Two of the four facts named here are established; two are not, and the difference is a wall rather than an omission.** A page holding a verifier across the whole trip, and the entry route's already-signed-in branch being the silent round trip — both driven in a real browser, in one scenario. The provider library hard-codes Google's authorization and token endpoints, so the leg through Google, and with it the `state` cookie's round trip and the callback landing on `/sign-in/return`, cannot be reached on a machine with no route off it. That is recorded in the suite's header rather than left to be rediscovered.

  **One scenario, deliberately.** The suite was written wide and cut back: what a single runtime decides belongs to that runtime's own tests. Four facts that looked like they needed a running deployment turned out not to — the well-known verification addresses are `convex/http.test.ts`, the substitution being absent by default is `convex/auth.test.ts`, and the entry route answering on a live session is `convex/signIn.session.test.ts`, all at a hundredth of the cost. What is left end to end is what a browser alone can say: a cookie carried on a top-level navigation to another origin, and a verifier held in session storage across it.

  **What the browser found — and what should have found it first.** `begin-sign-in` was absent from `SESSION_CAPABILITIES`, so the entry route refused every browser carrying a live session and its already-signed-in branch was unreachable code. The end-to-end run is what caught it, but it did not have to be: `signIn.test.ts` said establishing a session needed Better Auth's own component registered in the harness, and `@convex-dev/better-auth/test` exports a `register` helper that does exactly that. `signIn.session.test.ts` is now that test, and it catches the same defect in about a second.

- [x] 1.19 What the revised requirements asked for that the code did not yet do. The instance pins the platform issuer (`game_binding.platformIssuer`, checked before every other claim) because the SpacetimeDB host resolves verification material from the `iss` the token itself names and offers no allow-list — measured, not inferred, so a stranger publishing a discovery document had admissible tokens for any role in any game. The roster snapshot carries coach designations (`roster_coach`, `coachKey`), so a coach token's human half is checked and `coach:<anyone>:<any participating team>` is no longer admissible. `begin-sign-in-handoff` joins `PEER_FORBIDDEN_CAPABILITIES`, which closes the chain by which a Server holding a human's credential renewed it indefinitely without the human — and thereby makes a live session the only thing that can begin a renewal at all. `SESSION_CAPABILITIES` is derived from a `session` flag on the registry rather than kept beside it. `registry:designateAdmin` gives `platform_admins` its first writer outside the harness. And `apps/e2e` establishes that the host's websocket-token exchange preserves `iss`/`aud`/`sub`, which is what makes the SDK's default path admissible for a browser (`verification-without-shared-secrets#a-valid-signature-from-a-stranger-is-refused`, `admission-validation#coach-absent-from-the-snapshot-refused`, `peer-capability-ceiling#no-chain-reaches-what-one-step-may-not`, `token-lifetime-and-refresh#renewal-re-reads-the-session`, `anonymous-reach#session-reach-is-declared-with-the-capability`, `platform-admin-role#a-deployment-can-designate-its-first-admin`, `connect-time-validation#re-issuance-preserves-the-binding`)

**Deliberately not built here:**

- Team-administration functions (`principal-kind-gating#a-service-principal-cannot-administer-a-team`) do not exist yet. They arrive with `migrate-team-management` and hold the scenario by taking the default human-only kind gating, without declaring anything.
- The `write-centaur-state` capability is mintable and reaches nothing until `migrate-centaur-subsystem` lands its functions. `game-credential-scope` fixes the exactly-two grants, so it has to exist now.
- The four gameplay reducers stay absent; `actingTeam()` is the hook they call when their own change lands.
- `initialize_game` still belongs to migrate-game-lifecycle, and now inherits two obligations with the seed tables: the issuer it pins is the platform's, and the coach designations it writes include the platform admins standing at that moment — `platform-admin-role#implicit-coach-everywhere` is granted at issuance, and a game instance honours no platform-side role, so the snapshot is the only place that standing can reach one.
