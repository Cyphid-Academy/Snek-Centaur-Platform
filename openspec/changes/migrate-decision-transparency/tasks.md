## 2. The recorded decision surface — Convex (`packages/convex-centaur-state/`, mounted by `packages/convex-host/`)

- [ ] 2.1 Define the canonical computed-display-state record shape as one exported TypeScript type in `packages/convex-centaur-state/src/index.ts`: per candidate direction, the worst-case weighted score, the worst-case simulated world including its per-snake turn timestamps, and per contributing heuristic its display label, its normalised output in that world, and the portfolio weight in force when the score was composed. Two properties are the contract rather than the encoding — the type is self-sufficient (no field whose value a consumer would have to resolve against configuration) and absence is key-absence (never zero, never carried over). Whether the snapshot-constant weights and labels are hoisted out of the per-direction entries is storage mechanism `design.md` leaves plastic; the producer's coverage guarantee makes the heuristic set the same under every direction either way, so no encoding needs per-direction optionality (`decision-transparency/computed-display-state`, `#the-same-heuristics-under-every-direction`, `decision-transparency/extensible-state-slots`, `bot-framework/total-heuristic-coverage`)
- [ ] 2.2 Replace the `schema.ts` placeholder with the real Centaur-state schema entry for the per-snake display record (one row per game+snake, indexed for the team's live subscription), keeping the row's payload columns loose enough to hold whole simulated worlds while the shape of 2.1 is the authority on their contents. Holding simulated worlds in Convex during a live game is not a live-game mirror — they are the Server's own non-authoritative simulation output rather than a copy of instance state, and `design.md` carries that argument so review need not re-derive it (`global-invariants/state-confined-to-owning-runtime#convex-never-mirrors-a-live-game`). The row lifecycle around it is not this capability's work — seeding a game's rows with no pre-existing state at provisioning belongs to `game-lifecycle`, and retaining them past instance teardown for the life of the game record belongs to `replay-and-audit` (`decision-transparency/computed-display-state`, `decision-transparency/extensible-state-slots`, `replay-and-audit/replay-persistence#team-experience-outlives-teardown`)
- [ ] 2.3 Implement the full-replacement publish mutation on the Centaur function contract: every call overwrites the snake's record wholesale, no delta or merge path exists, and the contract imposes no per-turn or per-second throttle — with tests for wholesale replacement, for a rapid intra-turn burst all being accepted, and for a direction dropped from a snapshot leaving no residue (`decision-transparency/snapshot-full-replacement#any-snapshot-stands-alone`, `#absence-is-meaningful`, `decision-transparency/hosting-server-sole-writer#cadence-is-the-writers-choice`)
- [ ] 2.4 Enforce sole writership at the function contract, not in the library: the caller must be the hosting server of the team owning the snake, and every other identity and surface — operator clients, another team's server, any programmatic surface — is rejected, with negative tests per rejected identity kind (`decision-transparency/hosting-server-sole-writer#only-the-hosting-server-writes`); the credential mechanics the check validates are `identity-and-authorization`'s, consumed here
- [ ] 2.5 Fix the slot discipline in the component's `AGENTS.md` and its exported surface: the recorded decision outputs are exactly two platform-wide slots — this per-snake record and the append-only action log (whose own contract is `replay-and-audit`'s to author) — with no per-team table or per-team column ever added, and a test or lint asserting no team-keyed schema extension exists (`decision-transparency/extensible-state-slots#novel-bot-same-schema`, `#no-per-team-slots`)

## 3. Publishing the record — Centaur Server (`packages/centaur-server-lib/`)

- [ ] 3.1 Implement the snapshot builder over the framework's evaluation state: for each direction with a defined stateMap entry, emit the score, the single world that produced it, and that same world's per-heuristic outputs each paired with the weight and label the composition used — one world per direction entry, with a test that the outputs decompose the emitted score and never come from a fresher world, that the weighted contributions sum to the emitted score, that a weight or nickname edited between composition and publication does not change what is emitted, that the world's per-snake turn timestamps are inside the emitted record so a renderer needs nothing else to mark frozen snakes, and that every recorded direction carries the same heuristics at the same weights — the writer drops none of what composition handed it, and composition answers every candidate with every heuristic (`bot-framework/total-heuristic-coverage#no-candidate-goes-unscored`), which is what makes a per-heuristic comparison across directions computable from exactly this set (`decision-transparency/computed-display-state#per-direction-coherence`, `#weights-and-labels-are-recorded-not-joined`, `#timestamps-travel-with-the-world`, `#the-same-heuristics-under-every-direction`). The framework's own stateMaps, evaluation caches and dirty flags stay in-process scratch and are written to no store (`bot-framework/embedded-team-player`) — what persists is this published derivative, never the scratch
- [ ] 3.2 Implement deterministic worst-case-world selection: among active worlds tying for a direction's minimum, pick by a fixed rule, with a test that the same evaluation state produces byte-identical snapshots across runs and across process restarts; carry the concrete rule as mechanism with a `// design:` reference to this change's archive folder (`decision-transparency/computed-display-state#worst-case-world-is-deterministic`)
- [ ] 3.3 Wire publication to the dirty flag: a full snapshot goes out whenever the flag is set, without waiting on a submission or turn event, and selection promotion of a manual-mode snake yields fresh snapshots so the operator's displays converge off the unselected tier — the flag and the promotion rescoring are `bot-framework`'s, consumed here — and publishing never clears the flag, only the staging workflow does, so the natural set-flag→publish→clear wiring is a defect that starves the next submission pass (`decision-transparency/snapshot-full-replacement#dirty-flag-drives-publication`, `#selection-converges-the-display`, `bot-framework/score-composition#publishing-does-not-consume-the-news`)
- [ ] 3.4 Confine heuristic-contract-violation diagnosis to the hosting server's process log — no violation field on the record, no operator-interface surface, substituted values published like any other, with a test that a violating heuristic changes the published record only through its substituted value (`decision-transparency/published-slots-only#violations-stay-in-the-server-log`); the containment and substitution themselves are `bot-framework/author-fault-containment`
- [ ] 3.5 Pair every published snapshot with its snapshot-category action-log entry written in the same transaction as the record update, against the log contract `replay-and-audit` owns (`decision-transparency/hosting-server-sole-writer`, seam: `replay-and-audit/actors-write-own-entries#every-snapshot-logged`)

## 4. Team-private read scope — live vs post-game (Convex function contract)

- [ ] 4.1 Implement the read query and live subscription that serves a team its own snakes' display records, with read authorization enforced in the Centaur subsystem's own function contract as the single place — the displays of section 5 get no second, wider path (`decision-transparency/extensible-state-slots`, `decision-transparency/computed-display-state`)
- [ ] 4.2 Privacy enforcement as an explicit deliverable: negative tests that an opposing team's operator, an unauthenticated caller, and a spectator connection are all refused a team's recorded deliberation — heuristic weights, portfolio state, worst-case worlds, any display record — while the game is live, and that no display component can assemble another team's record from any surface it does hold (`decision-transparency/computed-display-state`, seam: `global-invariants/team-private-centaur-state#opponent-cannot-read-deliberation`, `live-game-observation/team-private-live-state#cross-team-reads-denied`)
- [ ] 4.3 Serve a bound team's coaches and platform admins from that same query — they read exactly what a member reads and no more. The grant is `live-game-observation`'s and is enforced once, in the Centaur subsystem's function contract; this capability's query rides that enforcement and defines no scope of its own (`live-game-observation/team-private-live-state#coach-parity-with-members`)
- [ ] 4.4 Implement the live-to-post-game read transition. The boundary is already settled in the corpus, so this is implementation and not a decision to reopen: while the game is playing the record is team-scoped and refused across teams; once the game is finished every participating team's display-state snapshots are readable by any authenticated user, and coach standing adds nothing further. Key the transition off the platform-held game status rather than a locally inferred one, and test both sides of the finished edge. Two things stay outside this query: the replay *surface*'s refusal of games still in play is `replay-and-audit`'s, and because scoring-time weights and labels are recorded, no path on either side of the edge reads the team's live configuration (`global-invariants/team-private-centaur-state#opponent-cannot-read-deliberation`, `#finished-games-release-only-what-is-published`, `replay-and-audit/finished-games-public#finished-means-open`, `#live-games-not-on-the-replay-surface`, `live-game-observation/team-private-live-state#finished-games-owe-coaches-nothing`, `game-lifecycle/status-authority`, `decision-transparency/computed-display-state#weights-and-labels-are-recorded-not-joined`)

## 6. The recorded shape as a consumer contract

- [ ] 6.1 Make the type of 2.1 the single published contract every consumer reads — the operator displays, `replay-and-audit`'s experience reconstruction and team-perspective replay, and any audit tooling. It is declared once, in the Convex component that owns the slot, and re-exported from `packages/centaur-server-lib/` for the Server and the replay consumers; a second declaration on the producer side is the drift this task exists to prevent (`decision-transparency/extensible-state-slots#novel-bot-same-schema`, `decision-transparency/computed-display-state`)
- [ ] 6.2 Bind the three displays through a read-only, mode-agnostic data source (live subscription or replayed snapshot) so no component carries a replay-aware branch and no mutation is expressible against the replay binding — the uniform live/replay abstraction is mechanism, and the read-only property is `replay-and-audit/replay-binding-mutation-free`'s to require. The examined selection of 5.7 stays outside this abstraction: it is client-local UI state with no data-source representation, which is what lets one component tree serve member, coach, and replay use sites unchanged (`decision-transparency/published-slots-only#no-client-recomputation`, `decision-transparency/examined-subject#never-persisted`)
