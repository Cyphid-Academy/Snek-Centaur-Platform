## 2. Staged-move log in the game instance (SpacetimeDB — `packages/stdb`)

- [ ] 2.1 Append-only staged-move table: one row per staging act carrying snake, direction, and the turn it was staged in; no update or delete path exists anywhere in the module, and retention is unbounded for the instance's life (`game-runtime/staged-move-log`, `#supersession-is-not-deletion`)
- [ ] 2.2 Effective-move read used by turn resolution and by every display consumer: the latest current-turn entry per snake, with prior-turn entries never carrying over and an unstaged snake falling to the engine's fallback direction; no cancel or clear reducer is offered (`game-runtime/staged-move-log#nothing-carries-over`, `#revocation-is-supersession`)
- [ ] 2.3 `stage_move` reducer: accepts from an admitted operator or bot connection of the snake's owning team only, deciding solely from the admission-time binding and never from call parameters; accepts any team snake irrespective of selection, which the instance neither stores nor checks; performs no legality evaluation; appends with no freeze window or final-submission barrier (`game-runtime/team-scoped-staging`, `game-runtime/staging-is-unvalidated`, `game-runtime/staged-move-log#accepted-until-declaration`)
- [ ] 2.4 Single-home audit: assert no staged-move mirror, buffer, or cache exists in Convex, in `packages/centaur-server-lib/`, or in the reference app — every consumer (board marker, supersession, resolution, the team's automated player) reads the instance's log (`game-runtime/staged-move-log#single-home`)

## 3. Operator coordination state (Convex — `packages/convex-centaur-state`, `packages/convex-host`)

- [ ] 3.1 Selection record schema replacing the `_schemaPlaceholder` stub: one record per snake per active game holding the current holder (or none) plus the snake's manual-mode flag, scoped to the owning team. Reconcile the stub's vocabulary in `packages/convex-centaur-state/src/index.ts` (`SnakeConfigRecord.currentSelectorUserId`, `SelectionState.selectorUserId`) with this delta's holder vocabulary and pick one name (`operator-control/exclusive-selection`)
- [ ] 3.2 Selection mutations: at most one holder per snake and at most one snake per operator enforced at the mutation contract in a single transaction, with holderless records counted as belonging to no one; displacement only on the caller's explicit request, otherwise rejected with the holder undisturbed; the caller's previous hold released inside the same transaction and observable as a deselection; no non-member ever named as holder (`operator-control/exclusive-selection`, `operator-control/selection-transfer`)
- [ ] 3.3 Manual-mode mutation: every snake starts each game automatic; entry and exit only by the snake's current holder; exit resumes automated staging and resets nothing else; selection and release both leave the flag untouched (`operator-control/manual-mode#fresh-game-all-automatic`, `#exit-resumes-automation`, `#manual-survives-losing-the-holder`, `operator-control/selection-is-view-only#selection-never-flips-manual`, `#release-changes-nothing-else`)
- [ ] 3.4 Clear every selection record for a game at game end, leaving no live selection state to masquerade as a historical record; hook it into the declared lifecycle finish bracket rather than any local status inference, and test that a game which reached `finished` has no surviving selection row (`operator-control/exclusive-selection#cleared-at-finish`, seam: `game-lifecycle/status-authority#no-backward-motion`, and `replay-and-audit` owns reconstructing selection history afterwards)
- [ ] 3.5 Captain boot mutation: severs the named operator's game-session connection exactly as a network drop would, writes no persistent operator state at all (no lockout, no cleared selection, no flag), permits immediate reconnection, and is refused for any non-Captain caller however invoked (`operator-control/captain-boot`)
- [ ] 3.6 Team-scoped read surface over selection and manual-mode state, for both team member clients and the team's hosting-server credential — this is the surface `bot-framework` consumes for manual-mode exclusion and attention tiers, so it must be a subscription, not a poll target (`operator-control/exclusive-selection`, `operator-control/manual-mode`)

## 4. Live operator interface (Centaur Server — `apps/centaur-server-reference`, `packages/centaur-server-lib`)

- [ ] 4.1 Dual-connection live binding: one connection to the game's SpacetimeDB instance for observation and staging, one to Convex for coordination state, each authenticated as the operator themself and neither's lifetime dependent on the other; no server relays, re-stages, or re-attributes any operation; the team's nominated host serves the interface and nothing more (`operator-control/operator-dual-connection`)
- [ ] 4.2 Live route with the availability bracket, driven by the lifecycle status the platform holds and never by a locally inferred one: prominent in the team's navigation from the moment the game is playing so an arriving operator finds it without searching, an explanatory empty state when the team has no playing game, and a terminal view with final outcome and replay path — carrying zero mutating affordances — the moment the game finishes (`operator-control/live-interface-availability`, seam: `game-lifecycle/status-authority`)
- [ ] 4.3 Board renderer over the connection's filtered observation surface (terrain, items, observable snakes), marking each owned snake's currently effective staged move and updating that marker live on every team client whatever the staging origin. Leave the decoration slots `decision-transparency` requires — candidate-cell colouring and a worst-case overlay layer — as extension points, not implementations, and parameterise them by snake rather than by who holds it, since those decorations are required for snakes nobody holds (`operator-control/board-and-move-interface`, `#marker-follows-any-origin`)
- [ ] 4.4 Four-direction staging affordance for the held snake: reflects the currently effective staged direction, marks immediately lethal directions as discouraged yet leaves them selectable — judged client-side with the shared engine's own move validation rather than a parallel implementation — and stages on every pick with no separate commit act, remaining changeable until the team's turn is over; make explicit in the affordance design that exploring and committing are indistinguishable to the game, and give the component no inert or preview-only pick state at all, so a decoration layer cannot add one (`operator-control/board-and-move-interface#lethal-discouraged-not-blocked`, `#exploration-is-staging`, `#no-second-direction-selector`, `game-runtime/staging-is-unvalidated`)
- [ ] 4.5 Selection gestures and gating: select an eligible team snake, release explicitly or by selecting another, obtain the operator's explicit confirmation before ever issuing the displacing form of the mutation, and render no direction candidates, staging controls, or per-snake edit affordances for any snake the operator does not currently hold (`operator-control/selection-transfer#confirmation-gates-displacement`, `operator-control/selection-is-view-only#no-affordances-without-holding`)
- [ ] 4.6 Manual-mode control and the cross-runtime ordering guarantee: the toggle reflects the flag and is editable by the holder alone; explicit entry stages nothing and locks whatever move is currently effective; a direction pick makes the snake manual with the transition effective no later than the staged move, so no window exists in which automation overwrites the operator. The interface implements no scheduling or automated staging of its own (`operator-control/manual-mode#staging-enters-manual-without-a-gap`, `#explicit-entry-locks-the-current-move`, `#interface-adds-no-automation`)
- [ ] 4.7 Operator presence and identity: a colour that is a pure function of (game, operator) — identical on every client, across reloads and reconnects, for the game's whole lifetime — used for both the connected-teammates presence display and the selection indication on held snakes, plus a connection-quality indicator measured entirely by the client with no server-held state behind it. The presence display is the component `turn-pacing`'s pacing header decorates (`operator-control/operator-presence-and-identity`)
- [ ] 4.8 Captain boot affordance, invisible to non-Captains, with the booted operator's own interface telling them they were removed and reconnection rejoining exactly as after a network drop (`operator-control/captain-boot#no-sticky-lockout`, `#captain-only`)

## 5. Downstream surface and seam integration

- [ ] 5.1 `turn-pacing` seam: the declaration path consumes exactly what the staged-move log holds at the declaration instant, boot's active-set and quorum consequences are pacing's to author, and the pacing header decorates this capability's presence display and the Captain-control cluster this capability's boot affordance sits in — agree the component boundary so the boot affordance is not built twice (`game-runtime/staged-move-log#accepted-until-declaration`, `operator-control/captain-boot`, `operator-control/operator-presence-and-identity`)
- [ ] 5.2 `bot-framework` seam: the automated player must never stage for a manual snake and never supersede an operator's current-turn move — confirm which side implements the guarantee (client ordering, an authorship check in the player, or both, all of which satisfy the requirement) and that the selection/manual subscription of 3.6 is what its attention tiers read (`operator-control/manual-mode`, `operator-control/selection-is-view-only`)
- [ ] 5.3 `decision-transparency` seam, now settled in spec — implement to it: a pick on this affordance stages the direction *and* sets the transparency layer's examined direction, while the examined direction is otherwise client-local state this capability neither reads nor writes. Wire the affordance so the decoration layer subscribes to picks rather than being able to originate them, and add a test that no code path outside this affordance reaches the staging reducer (`operator-control/board-and-move-interface#no-second-direction-selector`, `#exploration-is-staging`, seam: `decision-transparency/examined-subject#operator-pick-also-examines`)
- [ ] 5.4 `replay-and-audit` seam: the staged-move row carries the writer, accept time, and turn that attribution requires; selection, deselection, manual-mode toggle, and boot each write their action-log entry in the same transaction as the mutation. **Move staging is excluded from the action log** — remove `"StageMove"` from the `CentaurActionType` union in `packages/convex-centaur-state/src/index.ts`, which currently contradicts the single-home model (`game-runtime/staged-move-log#single-home`, `operator-control/exclusive-selection`, `operator-control/captain-boot`)
