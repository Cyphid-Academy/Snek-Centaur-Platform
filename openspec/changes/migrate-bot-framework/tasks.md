# migrate-bot-framework — Tasks

## 1. Pre-implementation

- [ ] 1.1 Review this change's artifacts with the author immediately before implementation begins, and refine this task breakdown then
- [ ] 1.2 Seam gate — agree or land the sibling contracts this capability consumes before coding against them: `operator-control` for the staged-move log, manual mode, exclusive selection, and view-only selection; `bot-configuration` for the effective per-snake portfolio and effective temperature this capability consumes as already-derived opaque inputs and for the compiled heuristic registry; `live-game-observation` for the team's filtered game view the framework subscribes to; `turn-pacing` for when a decided move is actually submitted **and** for the team's live automatic submission time allocation, which this capability's simulations declare as the turn's duration rather than holding a deliberation constant of their own; `decision-transparency` as the consumer of the stateMap, worst-case world, per-direction heuristic entries, and dirty flag
- [ ] 1.3 Settle Open Question 1 before the author-facing surface is published: this capability provides staleness-aware analysis primitives over partial states — the engine carries each snake's turn and deliberately grows no compensation helper — so what remains is which analyses they cover, whether raw per-snake turns stay reachable for authors writing their own, and whether the compensation rule is restated as the contract they implement or becomes internal to them. A fork consumes this surface, so it is a compatibility contract (bot-framework/frozen-snake-timestamps#head-start-compensation, centaur-server-runtime/forkable-reference-app#enumerated-surface-is-the-contract)
- [ ] 1.4 Confirm before any simulation code is written that the freezing decision has landed upstream: `revise-game-engine-contract` carries it as `game-engine/held-snakes`, resolution taking a set of snakes to hold as an *input* rather than a correction. Advancing an unmodelled snake in its last direction was rejected because it manufactures false safety — a candidate scored safe against an assumed straight-ahead opponent that would in fact have closed the escape. This capability's simulation calls hold; it never invents a direction for a snake it declined to model (bot-framework/foreign-snake-treatment#uninteresting-staged-move-freezes, bot-framework/frozen-snake-timestamps, game-engine/held-snakes)
- [ ] 1.5 Settle the two public-API decisions this change forces on the already-published `packages/centaur-server-lib/`: (a) that the delta's vocabulary is a breaking rewrite of the shipped typed skeleton's `Drive` / `Preference` / `Portfolio` / `Target` / `defineBot` shapes, and (b) which capability's requirement the heuristic *registration* entry points and registered-set projection discharge — this delta owns only the two abstractions, while `bot-configuration/registry-defines-availability` and `bot-configuration/registry-sync-insert-only` own the registry's content and sync semantics

## 2. Author-facing surface — `packages/centaur-server-lib/` (Centaur Server, published to forkers)

- [ ] 2.1 Re-author the exported heuristic vocabulary as the two abstractions and nothing else: a `Drive` parameterised over a snake target or a cell target carrying the author operations — reward, distance, motivation combiner, satisfaction predicate, target-eligibility predicate, self-direction nomination, foreign-move nomination — and a targetless, time-invariant `Preference` over the evaluated snake and a board; with no goal/fear discriminator anywhere in the runtime types (`bot-framework/heuristic-vocabulary`, `#two-target-types-only`, `#preferences-have-no-target`, `#goal-and-fear-share-one-runtime`). All domain types are consumed from `@cyphid/snek-engine`; the library mints no domain vocabulary of its own
- [ ] 2.2 Encode the scalar discipline on every author operation — reward, motivation, terminal reward, and Preference value bounded, distance non-negative and finite — with relative importance expressible only as a portfolio weight, and audit the framework's own computations for any reliance on monotonicity, symmetry, or other shape properties of author operations (`bot-framework/scalar-discipline`, `#importance-lives-in-weights`, `#no-shape-assumptions`). Weights live on the portfolio, never on a heuristic instance
- [ ] 2.3 Boundary guard around every author invocation, applied before any downstream consumer sees the value: clamp out-of-range numbers, substitute safe defaults for non-finite, wrong-typed, and missing values and for an invalid distance, coerce a non-boolean satisfaction result to false, and contain a thrown author exception as an invalid output of the operation that threw — so no raw invalid value and no exception can reach scoring, sampling, staging, or written decision state, and one broken heuristic degrades only its own contribution (`bot-framework/author-fault-containment`, `#nan-never-propagates`, `#thrown-exception-is-contained`)
- [ ] 2.4 Structured violation reporting into the hosting server's process log, deduplicated per turn per (snake, heuristic, violation kind) with the window resetting on turn change, and surfaced nowhere else — explicitly not into Centaur state and not onto any operator surface (`bot-framework/author-fault-containment#log-noise-is-bounded`)
- [ ] 2.5 Portfolio type the framework consumes: active Preferences with current weights, active Drives each with a concrete target and current weight, and one effective softmax temperature taken as a single opaque scalar the framework neither derives nor interprets; total for every owned snake at every moment, including a snake momentarily holding no Drives (`bot-framework/per-snake-portfolio`, `#portfolio-is-total`, `#temperature-is-opaque`). Seam: the derivation of weights and of the effective temperature is `bot-configuration`'s — this library only accepts them
- [ ] 2.6 Heuristic registration entry points and the serialisable registered-set projection the forkable app's interface and the registry sync consume, implemented only once 1.4(b) settles their ownership; the projection must not expose a handle that lets a consumer invoke an author implementation outside the framework process (`bot-framework/heuristic-vocabulary`)

## 3. Simulation kit — `packages/centaur-server-lib/` over `@cyphid/snek-engine`

- [ ] 3.1 Candidate self-direction enumeration per owned alive snake from the game's direction vocabulary, using the engine's own move-validity predicate for immediate lethality on the observed pre-turn board, deprioritising lethal directions but always retaining them so the candidate set is never empty; a direction lethal only contingent on a foreign snake's choice is never treated as immediately lethal (`bot-framework/candidate-directions`, `#all-lethal-still-decides`, `#contingent-death-is-not-filtered`). The engine owns the lethality rules; the framework owns only the ordering
- [ ] 3.2 One-turn-ahead world resolution through the engine's hypothetical entry point, holding every foreign snake with no directions in play (`game-engine/held-snakes`) and supplying an explicit direction for every snake it does model — the entry point refuses anything else, which is what stops a direction being invented for a snake the search declined to model: each scored world is the shared engine's resolution of the immediately next turn for one candidate self-move combined with one assignment of foreign moves, with foreign snakes having no directions in play held frozen in place, run entirely off-instance so nothing is committed — and with no deeper tree built, simulated, or scored (`bot-framework/worst-case-statemap#one-turn-horizon`, `bot-framework/foreign-snake-treatment`)
- [ ] 3.3 Per-snake turn timestamps on every simulated board the framework produces — advanced snakes at the simulated turn, frozen snakes at the prior turn — read from the engine's partial game state, which carries each snake's turn, so any consumer distinguishes fresh from held purely from the turns rather than from a framework-side wrapper type; plus the head-start compensation contract published to heuristic authors, so territory-style analysis advances each frozen snake's starting distance by its staleness instead of penalising it for the simulation's own fiction (`bot-framework/frozen-snake-timestamps`, `#staleness-is-readable`, `#head-start-compensation`). Coordinate the type's shape with `decision-transparency`, which records it. Include the shallow case in the tests deliberately: a state in which only the evaluated snake has advanced is the maximal staleness case, so whatever compensation the primitives provide must hold there rather than degrade to nothing (`bot-framework/total-heuristic-coverage#the-cheapest-evaluation-is-the-stalest`)
- [ ] 3.4 Declare the team's live automatic submission time allocation as the turn's duration and as every team's burn on every simulated resolution — read from the team's live game-scoped pacing values, the same value that bounds when the player actually submits, so the projection and the real deadline cannot drift apart, and snapshotted at the turn's start so every world simulated within one turn declares the same duration. Test the projection rather than the plumbing: a simulated board's clocks and consumed duration advance by the declared value, its own team's projected clock empties no later than a real game at the same burn would, a mid-turn retune leaves the turn's already-simulated worlds untouched and takes effect from the next turn, and a world one turn from a team's runout shows that team's snakes dead of the clock while worlds further out simply carry the remaining time (`bot-framework/simulated-turn-timings`, `#a-bound-it-honours-not-an-average`, `#one-declared-value-for-every-team`, `#the-turn-holds-one-allocation`, `#impending-runout-is-readable-before-it-is-an-ending`, game-engine/chess-timer#exhaustion-kills-the-teams-snakes, game-engine/turn-resolution-model). Seam: the allocation is `turn-pacing/live-pacing-parameters`' — read here, owned there, and its unset default is that requirement's too
- [ ] 3.5 Keep the freezing fiction positional: a frozen foreign snake's team burns its declared time like any other, and the compensation a frozen snake is owed applies to distance rather than to the clock. Worth an explicit test beside the head-start one, because the two rules look inconsistent until the reason is visible — a hold suspends a snake's turn, not the world's clock (`bot-framework/simulated-turn-timings#a-frozen-snake-does-not-freeze-its-teams-clock`, `bot-framework/frozen-snake-timestamps#head-start-compensation`, game-engine/held-snakes#a-held-snakes-team-still-spends-its-time)

- [ ] 3.6 Total heuristic coverage, with the shallow evaluation that makes it affordable: every heuristic in the snake's portfolio yields a number for every candidate direction being scored — no abstention, null, or skip path anywhere in the invocation loop — and a heuristic that nominates no foreign moves under a candidate is evaluated once over the partial state the engine's imagining entry point returns when only the evaluated snake is given a direction and every other snake is held, that one value standing as its value for every world scored under the candidate. Tests: an uninterested heuristic still contributes to the candidate; its shallow value is what enters each of that candidate's worlds; a heuristic exploring many foreign replies under one candidate and none under another answers for both; and no candidate's composed score is ever missing a portfolio member (`bot-framework/total-heuristic-coverage`, `#no-candidate-goes-unscored`, `#the-shallow-state-is-a-full-answer`, `#depth-is-selective-coverage-is-not`, game-engine/held-snakes, game-engine/turn-resolution-model). Seam: `decision-transparency/computed-display-state` records the per-direction entries this produces and its centred relative-impact column depends on their completeness

## 4. The embedded per-team player — `packages/centaur-server-lib/`, hosted by `apps/centaur-server-reference/`

- [ ] 4.1 Player lifecycle keyed by hosted team *and* live game — one player per hosted team per live game, each confined to its own team's Centaur state and its own team's authorized view of its own game — with evaluation caches, stateMaps, and dirty flags as in-memory scratch owned by the running process and written to no store, rebuilt from subscriptions alone after a mid-game restart and simply discarded when the game ends (`bot-framework/embedded-team-player`, `#restart-rebuilds-from-subscriptions`, `#scratch-dies-with-the-game`). Reconcile with the shipped entry point, which today keys a runner by game alone
- [ ] 4.2 The two inbound subscriptions and the single outbound write, with no polling anywhere: board state, staged moves, turn number, and chess clock from the team's game-instance connection, and portfolios, selection, manual mode, and the team's live game-scoped pacing values from the Convex Centaur-state subscription; staging a move for an automatic-mode snake as the only write ever performed against the game; no intermediary copy of the board; an operator's Centaur-state edit reaching the framework only as a committed effect on its subscription (`bot-framework/observe-and-stage-only`, `#no-shadow-board`, `#staging-is-the-only-game-write`, `#operator-edits-arrive-by-subscription`). Seams: the game-side subscription surface lands in `packages/stdb/` and the Convex-side in `packages/convex-centaur-state/`, both scaffolding today; view filtering is `live-game-observation`'s and the staged-move log is `operator-control`'s
- [ ] 4.3 The three reactive inputs and the world-activation predicate: per-snake interest map as the union of active Drives' foreign-move nominations, each foreign snake's commitment, and the portfolio weights — a world active exactly when every foreign move it assumes is in the interest map and consistent with that snake's commitment, activation evaluated as a predicate over current inputs so dormant worlds reactivate rather than being destructively discarded, and nothing outside the three inputs affecting the active set or the stateMap (`bot-framework/reactive-inputs`, `#nothing-else-is-reactive`, `#dormant-worlds-reactivate`)
- [ ] 4.4 Foreign-snake treatment and per-category commitment: every snake other than the evaluated one is foreign including alive teammates; a manual-mode teammate is committed exactly to its effective staged move only where that move is in the evaluated snake's interest map; automatic-mode teammates and opponents are always uncommitted, the framework's own staged move for a teammate never becoming that teammate's commitment; a foreign snake with no directions in play is frozen (`bot-framework/foreign-snake-treatment`, `#teammate-is-not-self`, `#automatic-teammate-stays-uncommitted`, `#uninteresting-staged-move-freezes`). Depends on `operator-control` for manual mode and the staged-move log
- [ ] 4.5 Turn-scoped evaluation lifecycle: work accumulated within a turn only grows, the turn number observed on the game subscription is the sole validity key and its change the only reset, a reconnection resurfacing the same turn number discards nothing, and no world simulated against a previous board ever contributes to a new turn's scores (`bot-framework/turn-scoped-evaluation`, `#reconnect-same-turn-keeps-work`, `#turn-change-is-the-only-reset`)

## 5. Scoring, decision, and attention — `packages/centaur-server-lib/`

- [ ] 5.1 Per-snake stateMap and its scoring: each candidate direction's entry the minimum weighted score over its currently active worlds, updated continuously through the turn as inputs change, undefined until at least one active world has been evaluated for it — never zero and never a guess — with higher entries better and the entry improving when an input change deactivates the world that was its minimum; the weighted score itself the linear sum over the portfolio of each heuristic's weight times its value in that world, a Drive contributing its motivation and a Preference its value, so a zero weight silences a heuristic exactly and every portfolio member is present in every candidate's composition (`bot-framework/worst-case-statemap`, `#undefined-is-not-zero`, `#worst-case-tracks-activation`, `bot-framework/score-composition`, `#zero-weight-silences`, `bot-framework/total-heuristic-coverage#no-candidate-goes-unscored`)
- [ ] 5.2 Drive satisfaction: in a satisfied simulated world the Drive's contribution is its terminal reward, bypassing distance and the motivation combiner; each turn every Drive's predicate is also evaluated against the observed authoritative board and each Drive satisfied there is retired for the turns that follow, while satisfaction in merely simulated worlds retires nothing (`bot-framework/drive-satisfaction`, `#terminal-reward-bypasses-motivation`, `#simulated-satisfaction-does-not-retire`)
- [ ] 5.3 Retirement as in-memory deactivation, with no write path at all: the retired set is derived from the current turn's observed board into the process-owned working portfolio, never latched across turns and never sent anywhere, so a Drive returns by itself on a later board that no longer satisfies it and a restarted process re-derives the set from what it observes. Test that no Centaur-state mutation is issued on retirement and that the portfolio the framework was handed compares equal before and after (`bot-framework/drive-satisfaction#retirement-reverses-with-the-board`, `#retirement-writes-nothing`). Seam: the record's side of this is `bot-configuration/per-snake-portfolio-record#satisfied-drive-keeps-its-record`, and the operator-facing marking is `bot-configuration/drive-management-interface#omitted-drives-stay-visible` — named here, built there
- [ ] 5.4 Dirty flag: set whenever a rescoring pass actually changes any of the snake's stateMap entries, left untouched when a pass leaves every entry equal, and — within a turn — cleared by nothing this capability does. Expose it so the staging workflow clears it on its staging acknowledgement and a snapshot publication cannot, with a test that a publication while the flag is set leaves it set (`bot-framework/score-composition`, `#unchanged-scores-set-no-flag`, `#publishing-does-not-consume-the-news`). Seams: the clearing act itself is `turn-pacing/scheduled-submission`'s and the publication is `decision-transparency/snapshot-full-replacement`'s
- [ ] 5.5 Softmax decision for an automatic-mode snake: sample over the currently defined stateMap entries with probability proportional to the exponential of the entry divided by the effective temperature, excluding undefined entries so sampling over a partial stateMap is legitimate; with no entry defined, stage the snake's last direction, or stage nothing when none exists yet and leave the engine's fallback to resolve the move (`bot-framework/softmax-decision`, `#partial-statemap-is-decidable`, `#zero-knowledge-fallback`). Seam: *when* a decision is taken and staged is `turn-pacing`'s
- [ ] 5.6 Attention ordering over owned snakes: automatic-mode served continuously and first, operator-selected manual-mode next, unselected manual-mode last, with no owned snake starved indefinitely within its tier, and selection promoting or demoting a manual snake immediately rather than at a turn boundary or scheduling epoch (`bot-framework/attention-tiers`, `#manual-snakes-still-served`, `#selection-shifts-attention-immediately`). Depends on `operator-control` for selection state
- [ ] 5.7 Selection promotion of a manual-mode snake: re-evaluate which evaluated worlds are active against the current inputs, applying interest-map and commitment drift accrued while unselected, rescore the stateMap, and prioritise the outstanding evaluation — affecting attention and decision state only, never staging a move, and leaving an operator-staged move present at promotion untouched throughout (`bot-framework/selection-promotion`, `#drift-reconciled-on-promotion`, `#promotion-never-stages`, `#staged-move-survives-promotion`)
