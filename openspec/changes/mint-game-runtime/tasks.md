# mint-game-runtime — Tasks

## 1. Pre-implementation & seam gates

- [ ] 1.1 Review this change's artifacts with the author immediately before implementation begins, and refine this task breakdown then
- [ ] 1.2 Seam gate — capabilities that must be implemented or agreed first, and which archive before this change: `game-lifecycle` (instance provisioning, the once-only initialization that writes turn 0 and makes the game playable, the end-condition definition this capability's freeze declares, the finish notification and the persistence-gated teardown), `identity-and-authorization` (connection admission and the role-bound privileges the staging check rests on), `test-sequences` (the canonical encoding and the replay-check this capability's determinism obligation is evaluated by), and `revise-game-engine-contract` — which adds the engine surfaces this capability cannot be implemented without: the as-if-ended per-turn score, the hazard-damage event kind, the held-snake representation, the `maxGameDurationMs` parameter, and the two timing parameters on the resolution entry points that this capability measures and supplies
- [ ] 1.3 Confirm the runtime home this plan assumes: every requirement in this capability is realised in the game's own SpacetimeDB instance module, with no Convex and no hosting-server code in scope — the pacing, operator, framework, transparency and replay capabilities own everything outside it
- [ ] 1.4 Confirm at review that the staged-move read policy is enforced against this capability's log from the observation story's filtering cluster, where it now lives, and that no read rule was left behind in the operator story when the log moved (`game-runtime/staged-move-log`, `live-game-observation/staged-move-privacy`)

## 2. Module foundation (SpacetimeDB module — deepening what `game-lifecycle` stood up)

- [ ] 2.1 Generate and wire client bindings for every consumer of the instance's contract — replacing the `codegen` no-op stub — and pin the generated output to the build so a schema change that breaks a consumer fails the build rather than a running client
- [ ] 2.2 Stand up the reducer test harness the concurrency requirements need: a harness that drives two reducer invocations into one transaction window, so the exactly-once trigger and the idempotent declaration can be tested as races rather than as sequences (`game-runtime/exactly-once-resolution#any-mix-one-trigger`, `game-runtime/turn-declaration#second-declaration-is-a-no-op`)
- [ ] 2.3 Define the instance's table set: the append-only staged-move log, the per-team clock and budget working state, the per-team declaration state, the turn-keyed snapshot / item-lifetime / event / aggregate tables, and the per-connection attribution table — every one instance-local, with nothing platform-wide reachable from inside (`game-runtime/staged-move-log`, `game-runtime/turn-keyed-game-record`, `game-runtime/connect-time-attribution`)
- [ ] 2.4 Enumerate the module's mutating surface as a closed set — the once-only initialization that `game-lifecycle` owns, plus staging, declaration and resolution — and add a test that fails if any other write path against committed turn state exists (`game-runtime/resolving-transaction#no-second-writer`)

## 3. Admission and staging

- [ ] 3.1 Resolve every admitted connection to an agent value at admission — the team identity for a bot connection, the operator's identity for an operator connection — and write an attribution entry that is never mutated or deleted, with reconnection appending a fresh entry (`game-runtime/connect-time-attribution`, `game-runtime/connect-time-attribution#reconnect-appends-fresh`)
- [ ] 3.2 Implement the staging reducer's team-granular authorization from the connection's admission-time binding alone, rejecting any per-call assertion of a different team, and holding no notion of which member within the team is acting (`game-runtime/team-scoped-staging`, `game-runtime/team-scoped-staging#spoofed-parameters-rejected`)
- [ ] 3.3 Implement the append-only staged-move log: every staging appends, nothing is ever edited or cleared, no cancel operation exists, and the effective move is the latest current-turn entry with no carry-over from prior turns (`game-runtime/staged-move-log`, `game-runtime/staged-move-log#supersession-is-not-deletion`, `game-runtime/staged-move-log#nothing-carries-over`)
- [ ] 3.4 Stamp every log entry with its writing agent, the wall-clock acceptance time, and its turn (`game-runtime/staged-move-attribution`, `game-runtime/staged-move-attribution#sub-turn-staging-history`)
- [ ] 3.5 Accept any vocabulary direction for any living team snake with no legality evaluation, including immediately lethal ones, and add a test that a wall-bound direction is appended and resolves to a death (`game-runtime/staging-is-unvalidated#lethal-direction-accepted`)

## 4. Clock and declaration

- [ ] 4.1 Realise the chess timer in instance state alone: hold each team's budget and per-turn clock exactly as the last resolution committed them, derive the running clock by subtracting measured elapsed time, and write neither anywhere but in a resolution's commit — so no reducer between turns applies budget, carve-out or banking arithmetic of its own. Test that budget plus the observed clock equals total remaining time when read mid-turn, at carve-out and at declaration (`game-runtime/in-game-clock`, `game-runtime/in-game-clock#invariant-at-every-instant`, `game-runtime/in-game-clock#one-copy-of-a-teams-time`)
- [ ] 4.2 Start turn 0's clocks at the moment the game becomes playable with no grace period — the once-only initialization that makes it playable is `game-lifecycle/instance-initialization`'s; this capability contributes the clock start inside it (`game-runtime/in-game-clock#clocks-run-from-playability`)
- [ ] 4.3 Implement autonomous clock-expiry detection as an instance-scheduled reducer armed at each turn start for the next expiring team, firing with no client connected and re-arming on every turn transition (`game-runtime/in-game-clock#no-external-timekeeper`, `game-runtime/turn-declaration#expiry-detected-autonomously`)
- [ ] 4.4 Implement the declare-turn-over operation: owning-team connections only, banking the remainder, idempotent within a turn under a guard evaluated inside the reducer transaction, snakeless teams auto-declared at each turn's start, and every declaration stamped with its kind (`game-runtime/turn-declaration`, `game-runtime/turn-declaration#only-the-team-declares`, `game-runtime/turn-declaration#snakeless-team-never-blocks`)
- [ ] 4.5 Record the authenticated caller on every accepted declaration even though the check branches on nothing finer than the team (`game-runtime/turn-declaration#team-granular-but-never-anonymous`)

## 5. The resolving transaction

- [ ] 5.1 Make the all-declared condition the sole resolution trigger, firing exactly once per turn under any mix of declaration kinds, with the already-resolved guard inside the resolving transaction; test the concurrent-final-declaration race (`game-runtime/exactly-once-resolution`, `game-runtime/exactly-once-resolution#nothing-else-resolves`)
- [ ] 5.2 Assemble the resolved state from the instance's own records and seeded parameters only — no external call, no caller-supplied board — and obtain the outcome from the shared engine build, never a parallel implementation (`game-runtime/resolving-transaction#assembled-from-instance-state-alone`, `game-runtime/resolving-transaction#outcome-is-the-engines`)
- [ ] 5.3 Commit every consequence of the turn in that one transaction — snapshots, events, item-lifetime stamps, aggregate rows, budgets and the next turn's clocks, and end detection — and add a test that asserts the committed row set is complete for a turn exercising every consequence at once (`game-runtime/resolving-transaction`, `game-runtime/resolving-transaction#one-commit-carries-everything`)
- [ ] 5.4 Implement the turn bracket at the commit: a late staged move or declaration lands in the new turn or is rejected, never reordered into committed history, and the next turn opens within the same commit with incremented budgets and carved clocks already running (`game-runtime/next-turn-bracket`, `game-runtime/next-turn-bracket#no-silent-reordering`, `game-runtime/next-turn-bracket#next-turn-opens-with-the-commit`)
- [ ] 5.5 Reject every gameplay operation from the end-detecting commit onward with zero grace window, and test the staged move that races that commit — the end condition itself is `game-lifecycle/game-end-boundary`'s (`game-runtime/game-over-freeze`, `game-runtime/game-over-freeze#zero-grace-window`)

- [ ] 5.6 Measure the two timing quantities the engine's entry points require and supply them with the assembled state: each team's own elapsed deliberation for the turn, and the turn's own length, both taken on the instance's clock from the anchors task 4.2 establishes. Measured values only — never a configured nominal, never the same number for both, never the per-turn cap standing in for what a team spent (`game-runtime/turn-timing-measurement`, `game-runtime/turn-timing-measurement#two-quantities-not-one`, `game-runtime/resolving-transaction#assembled-from-instance-state-alone`)
- [ ] 5.7 Read every ending out of the engine's outcome, including the two that depend on time, and add **no** comparison of a measurement against the configured limit anywhere in the reducer — with a test that a game whose declared durations reach a short duration limit ends at a turn commit with a complete final-turn record, its final scores taken from that turn's aggregate rows, and the freeze biting from that commit with no case of its own (`game-runtime/turn-timing-measurement#measured-here-decided-there`, `game-runtime/per-turn-scoreboard#live-score-reads-as-if-ended`, `game-runtime/game-over-freeze#no-turns-after-end`, game-engine/game-end-conditions#the-duration-limit-is-an-ending-like-any-other, game-engine/scoring#standing-score-at-any-turn)
- [ ] 5.8 Arm no scheduler that resolves or terminates on a deadline, and test the mid-turn case: the limit falling due while a team is still deliberating resolves nothing, the turn running on to its own all-declared or expiry end (`game-runtime/turn-timing-measurement#the-deadline-resolves-no-turn`, `game-runtime/turn-timing-measurement#no-external-deadline-keeper`, `game-runtime/exactly-once-resolution#nothing-else-resolves`)

## 6. The turn-keyed record

- [ ] 6.1 Write the per-turn historical rows the record enumerates — snake snapshots, item lifetimes, post-turn budgets with declaration kind and timestamp, turn start and resolution-start wall-clock, and the board layout written once at initialization — with unbounded retention for the instance's life (`game-runtime/turn-keyed-game-record`, `game-runtime/turn-keyed-game-record#items-derivable-at-any-turn`, `game-runtime/turn-keyed-game-record#unbounded-retention`)
- [ ] 6.2 Enforce append-only at the storage layer, with the item destroyed-turn stamp as the single permitted touch of an already-written row, and a test that no other write path can mutate a committed row (`game-runtime/append-only-record`, `game-runtime/append-only-record#the-single-stamp`)
- [ ] 6.3 Implement the closed turn-event set — the engine's vocabulary plus a survivors-only hazard-damage event — with each event carrying enough to visualise its outcome without diffing snapshots, and no extensible kind. **Seam:** the engine's event vocabulary is extended by `revise-game-engine-contract`, which folds first (`game-runtime/turn-event-record`, `game-runtime/turn-event-record#hazard-damage-never-double-counted`, `game-runtime/turn-event-record#no-new-kinds-by-extension`)
- [ ] 6.4 Derive the canonical event order from event data alone with no stored sequence column, and test that two independent reproductions of a game order every turn identically (`game-runtime/canonical-event-order`, `game-runtime/canonical-event-order#derived-not-stored`, `game-runtime/canonical-event-order#stable-across-replays`)
- [ ] 6.5 Attribute each movement event to the agent whose staged move was consumed, with an empty attribution meaning fallback and nothing else (`game-runtime/staged-move-attribution#bot-and-operator-distinguishable`, `game-runtime/staged-move-attribution#fallback-moves-attributed-to-no-one`)
- [ ] 6.6 Write one aggregate row per rostered team per completed turn — zero-filled for eliminated teams, normalised as-if-ended, computed over the true alive set including invisible snakes — inside the resolving transaction, as a durable record fact rather than a subscription projection. **Seam:** the as-if-ended per-turn score needs an engine surface that `revise-game-engine-contract` adds (`game-runtime/per-turn-scoreboard`, `game-runtime/per-turn-scoreboard#eliminated-teams-zero-filled`, `game-runtime/per-turn-scoreboard#rows-outlive-the-live-audience`)
- [ ] 6.7 Read the per-turn score from the shared engine's standing-score calculation rather than normalising a second time in the instance: the engine defines a standing score at any turn and `revise-game-engine-contract` exports it, so the aggregate row calls one function and a mid-game figure can never diverge from the figure the game is decided by. This work cannot start until that lands (game-runtime/per-turn-scoreboard#live-score-reads-as-if-ended, game-engine/scoring#standing-score-at-any-turn, global-invariants/one-shared-engine#no-parallel-implementation; seam: `revise-game-engine-contract`)
- [ ] 6.8 Unresolved — settle with the author how a forfeited-but-rostered team appears in the aggregate rows: this requirement demands a row for every rostered team every turn, while the engine's scoring excludes forfeited teams from every term, so "zero-filled row" and "excluded from the normalisation denominator" must be implemented as two separate facts rather than conflated (game-runtime/per-turn-scoreboard#eliminated-teams-zero-filled; seam: game-engine/scoring)
- [ ] 6.9 Make each row a durable record row of the game's history rather than a view materialised for whoever is subscribed — the persisted replay renders these rows long after the instance is gone, and nothing downstream may re-derive them (game-runtime/per-turn-scoreboard#rows-outlive-the-live-audience, game-runtime/turn-keyed-game-record#aggregates-are-recorded-not-recomputed; seams: replay-and-audit/once-at-end-export#aggregates-travel-with-the-record carries them out of the instance, and live-game-observation/scoreboard-sole-aggregate-authority delivers them while the game runs)

- [ ] 6.10 Record each turn's supplied timings — its duration and each team's burn — among the turn-keyed rows, since they were inputs of that turn's resolution on the same footing as its staged moves; test that a turn reproduces from the record alone, with no timing re-measured or defaulted, and that the ending is read from the recorded outcome rather than recomputed from a clock (`game-runtime/turn-keyed-game-record#the-timings-are-recorded-because-they-were-inputs`, `game-runtime/replay-sufficiency#nothing-else-consulted`, test-sequences/sequence-format#timings-are-inputs-not-metadata)
