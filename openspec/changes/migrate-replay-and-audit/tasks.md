## 2. The in-instance record — deliberately not built here

Moved out. Everything the resolving transaction accumulates belongs to
`game-runtime`: the turn-keyed record and its unbounded retention, the closed
turn-event set, the derived canonical event order, the per-turn aggregate rows,
replay sufficiency with its one canonical encoding and the bit-identical
reproduction check, and connect-time and staged-move attribution — see
`mint-game-runtime` tasks §§2–3 and §§6–7. The append-only guarantee over rows a
game's own runtime commits is `game-runtime/append-only-record`; this
capability's `replay-and-audit/append-only-history` covers only the two
platform-persistent histories, the team action log and the persisted replay, and
is planned in §4 and §5.1.

Two corollaries, so neither is re-derived wrongly: `test-sequences`
is **not** a dependency of this capability — the canonical-encoding contract
travelled with `replay-sufficiency` — so extracting the recorded-run codec, seed
derivation and replay-check out of `apps/visual-tester/src/lib/test-sequences/`
is that plan's task, not this one's; and this capability writes nothing inside
`packages/stdb` except the export path of §4.1. Work here begins at the egress:
the finished record is taken as given, and the first act is §3's defensive check
on what arrives.

## 3. What arrives at the boundary (Convex — `packages/convex-host`)

- [ ] 3.1 Agent-form persistence: the Convex-side persistence path verifies, as a defensive check before writing, that every attribution in the record is in agent form and surfaces a non-conforming record as a defect rather than persisting it; persisted attribution is bound to the game's roster snapshot so later roster edits, team archival, or account changes never rewrite who did what — tested with a member removed after the game finished (`replay-and-audit/agent-form-persistence`, `#defensive-check-at-persistence`, `#removed-member-still-attributed`). The producing half is not this change's: `game-runtime/connect-time-attribution` resolves the agent value at admission and `game-runtime/staged-move-attribution` carries it on every recorded act, so this check is a boundary assertion on a property the instance already owes, never a second resolution step. Seam: `identity-and-authorization/roster-snapshot-binding` and `game-lifecycle/roster-snapshot` own the snapshot this binds to

## 4. Once-at-end export and replay persistence (`packages/stdb` export path, `packages/convex-host` + `packages/convex-snek-platform`)

- [ ] 4.1 The single sanctioned egress: bundle the complete record into the terminal notification exactly once at game end, with no incremental, per-turn, or partial export path existing anywhere for any part of it; every accumulated part travels — each completed turn's per-team aggregate rows, the full staged-move log, and the attribution records — and visibility filtering is bypassed so invisible snakes' states are included; the per-game seed travels in the export though no game client can observe it while the game runs; an error outcome bundles no replay data (`replay-and-audit/once-at-end-export`, `#nothing-leaves-per-turn`, `#filter-bypassed-for-export`, `#aggregates-travel-with-the-record`, `#seed-secret-live-exported-post`, `#error-outcome-exports-nothing`). Seam: `game-lifecycle/finish-notification` owns the notification, its credential, and the no-scores half of error handling
- [ ] 4.2 Platform-only retrieval: the export is reachable only under the platform's own privilege, distinct from every gameplay admission, and no operator, bot, spectator, or coach connection can retrieve it — which rests on the instance's client read surface being filtered views only, with the raw record and attribution tables outside it (`replay-and-audit/once-at-end-export#platform-only-retrieval`). Seam: `live-game-observation/filtered-views-are-the-only-surface` and `identity-and-authorization/admission-records-private` are what make a per-role check list unnecessary. Build this as a retrieval the platform can *pull*, not only a payload the instance pushes: `game-lifecycle/stale-game-recovery#live-instance-yields-the-record` fetches the same complete record from a still-standing instance whose notification was lost, and that is the same one sanctioned egress arriving by a second caller — not a second export path, and not a licence to read a game in play
- [ ] 4.3 Persist the exported record as the game's replay bound to its persistent game record, starting only after the instance has signalled its terminal state and completing before teardown; no path begins persistence for a game still in play (`replay-and-audit/replay-persistence`, `#not-before-terminal-signal`). Name the seam precisely in the code and in `// spec:` citations: this capability owns **record sufficiency** — what the persisted record must contain and the shape of the bundled replay data, including its absence on error outcomes — while `game-lifecycle/teardown-after-persistence` owns only the bracket that keeps the instance alive until persistence is confirmed, and `game-lifecycle/game-record` the record the replay binds to. The scaffolded replay row in `packages/convex-snek-platform` carries an opaque turn log and nothing else; defining what it actually holds — aggregates, staged-move log, attribution, seed — is this task, and every consumer in §6 reads that shape
- [ ] 4.4 Post-teardown permanence: the persisted replay and the game's team-experience records — the action log and the display-state snapshots — survive teardown for the life of the game record, teardown cascades into none of them, and no code path from replay viewing reaches for a game instance (`replay-and-audit/replay-persistence#viewing-never-consults-an-instance`, `#team-experience-outlives-teardown`). Confirm what "display-state snapshots" resolves to: `decision-transparency/snapshot-full-replacement` keeps only the latest published snapshot per snake, so the *history* the reconstruction guarantee needs is the action log's snapshot entries, not that record

## 5. Team action log and experience reconstruction (Convex — `packages/convex-centaur-state`, writers in `packages/convex-host`, `packages/centaur-server-lib`, `apps/centaur-server-reference`)

- [ ] 5.1 Per-game team action log at sub-turn wall-clock resolution: every entry carries the game, the turn, the acting identity and its kind (operator, or the team's server acting as its bot), and a wall-clock timestamp; the category set covers operator arrivals and departures (the departure carrying its cause — deliberate leave, lost connection, or Captain boot), snake selection and deselection, manual-mode toggles, Drive addition and removal, heuristic weight and activation changes carrying both old and new values, temperature-override changes, per-operator tempo changes, Captain boots, team-side turn submissions, and computed-display-state snapshots — with no move-staging category, since staged moves live solely in the instance's log; entries have no edit or delete mutation at all (`replay-and-audit/team-action-log`, `#sub-turn-resolution`, `#tempo-and-boot-are-clock-anchored`, `#every-departure-is-logged-however-it-happened`, `#weight-change-carries-before-and-after`, `#move-staging-excluded`, `replay-and-audit/append-only-history#action-log-entries-never-corrected`). Fix each category's entry payload so the entry is self-sufficient evidence of its own transition — in particular the snapshot category carries the full published snapshot, which the requirement's minimum field list does not state. The scaffolded action-type union and entry row in `packages/convex-centaur-state` are the starting point and are wrong in three ways: no arrival or departure category exists, a single actor-user field cannot express the team's server acting as its bot, and the union still carries a move-staging member (whose removal `migrate-operator-control` §5.4 also claims — agree one owner for that edit rather than doing it twice)
- [ ] 5.2 Writer discipline and transactional pairing at the Convex mutation contract: each entry is written by the actor it describes under that actor's own credential, the team's hosting server writes the snapshot category exclusively and every published snapshot produces its entry, every mutation of recorded team state writes its entry in the same transaction as the mutation, and no back-fill or reconciliation path exists that could supply an entry an actor's own write did not produce (`replay-and-audit/actors-write-own-entries`, `#dropped-entry-means-no-mutation`, `#server-never-ghost-writes`, `#every-snapshot-logged`). Implement the single exemption explicitly and in one place — the departure entry, written by Convex itself as it observes the operator's coordination connection end, since no departing client can be relied on to write it (`replay-and-audit/actors-write-own-entries#the-one-entry-its-actor-cannot-write`). Seams: `decision-transparency/hosting-server-sole-writer` for snapshot writership, `operator-control` and `turn-pacing` for the mutations whose transactions these entries join
- [ ] 5.3 Experience-reconstruction query over the persisted replay plus the action log, answering at any wall-clock moment — inside a turn, not only at boundaries — each operator's selected snake, each snake's manual-mode flag, active Drives with targets and weights, heuristic activations and weight overrides, temperature override, display state as last written before that moment, the staged moves and who staged them (read from the game record), and the active-operator set with each operator's tempo, folded from the log's own arrival and departure entries; with guard-rail tests that board contents, snake bodies, and outcomes are never derived from the log, and that presence is never inferred from a lull in an operator's activity (`replay-and-audit/experience-reconstruction`, `#any-moment-not-just-boundaries`, `#selection-history-from-the-log-alone`, `#presence-is-read-not-guessed`, `#board-truth-from-the-game-record-only`)
- [ ] 5.4 Connection events in Convex — the producer 5.3 and the shadow rule both read. On an operator joining the team's game session, write an arrival entry from that operator's own credentialed client, in the same transaction as the tempo write `turn-pacing/operator-tempo#flow-on-every-rejoin` already performs; on that operator's Convex coordination connection ending, write a departure entry from Convex itself, carrying whether it was a deliberate leave, a lost connection, or a Captain's boot. Convex is the writer because the log is Centaur state and the game instance may not egress mid-game; a Captain boot therefore produces two entries — the Captain's own boot entry and the booted operator's departure entry — which must not be conflated (`replay-and-audit/team-action-log#every-departure-is-logged-however-it-happened`, `replay-and-audit/actors-write-own-entries#the-one-entry-its-actor-cannot-write`, `replay-and-audit/experience-reconstruction#presence-is-read-not-guessed`, `replay-and-audit/team-perspective-replay#shadows-in-original-colours`). Seams: `operator-control/operator-dual-connection` owns the connection whose lifetime is observed, `operator-control/captain-boot` the boot that severs it, `global-invariants/game-instance-hermeticity#no-egress-before-game-end` the reason the instance cannot be the writer. Settle the liveness the connection layer must give Convex — how promptly a dropped connection is observed, and that a drop is eventually recorded rather than silently lost — since the reconstruction's accuracy is bounded by it

## 6. Replay surface: discovery, viewer, modes, timeline (`apps/centaur-server-reference` + `packages/centaur-server-lib`, reading `packages/convex-snek-platform`)

- [ ] 6.1 Finished-game readability and the one viewer's gate: a finished game's full record — board-level replay plus every participating team's action-log entries, display-state snapshots, and staged-move history — is readable by every authenticated user; one unified viewer serves every entry point with board-level and team-perspective as modes rather than separate applications; it opens only for a finished game with a persisted replay (so an error outcome opens nothing); a game still in play is refused by the replay surface entirely; and a direct-link affordance produces a URL that takes any authenticated user to that game's replay (`replay-and-audit/finished-games-public`, `#finished-means-open`, `#direct-link-grants-any-finished-replay`, `#live-games-not-on-the-replay-surface`, `replay-and-audit/unified-replay-viewer`, `#one-viewer-not-two`, `#finished-with-replay-only`, `#team-perspective-participants-only`). Two things this viewer deliberately does not build: it is a surface inside the one application `application-shell` owns, not an application of its own; and forfeit presentation within it is `tournaments`' diff over these surfaces once they exist (`tournaments/forfeit-scoring#the-replay-shows-the-forfeit`)
- [ ] 6.2 Per-hosted-team game-history listing: completed games in reverse chronological order, listed for a user exactly when they were a member at the time of the game per the roster snapshot or are a current member, showing room, date, opposing teams, the team's result, the normalised score as the headline value against par 1.0 in real-valued display, and aggregate body length as the secondary stat; selecting a listing opens the viewer defaulting to team perspective (`replay-and-audit/team-game-history`, `#historical-or-current-membership`, `#listing-is-discovery-not-access`, `#normalised-score-headline`). Seams: `game-lifecycle/roster-snapshot` for membership-at-the-time, `game-lifecycle/game-record` for the outcome and timestamps, `rooms-and-matchmaking` for the room. Confirm where aggregate length comes from — the recorded outcome carries scores, so the secondary stat plausibly requires the replay's final aggregate row, which a cheap listing query should not have to open. Build the query scope-parameterised from the start: `accounts-and-profiles` plans the player and team profile histories as the *same* query with a different scope (`accounts-and-profiles/player-profile`, `accounts-and-profiles/team-profile`), and it folds after this change, so the eligibility rule and the normalised-score headline convention are authored here once and reused rather than reimplemented there
- [ ] 6.3 Replay data binding with no mutation surface at all — mutation is structurally absent rather than present and refused, so no invocable write exists for a replay client and no runtime guard stands between a viewer and a write; interface components get their read-only behaviour from the binding, never from a per-component replay branch (`replay-and-audit/replay-binding-mutation-free`, `#absence-not-guard`, `#read-only-is-not-per-component`). This is the replay instance of a promise `application-shell` already makes for every surface, so implement it as a source behind the one binding rather than a binding of this capability's own (`application-shell/one-state-binding#absence-not-refusal`, `#a-surface-does-not-know-its-source`). Record in code comments that this is an architecture property, not a security boundary — enforcement stays with the owning runtimes per `global-invariants/security-enforced-outside-the-library`
- [ ] 6.4 Board-level mode sourced from the persisted replay alone, functional long after teardown: board terrain, snakes, items, hazards, and fertile tiles at the selected turn; the per-team scoreboard with normalised score as headline at par 1.0 and aggregate length secondary, from the recorded rows; and a per-turn event log listing the turn's events from the closed enumeration with no kind unrepresentable, visually consistent with live spectating (`replay-and-audit/board-level-replay`, `#functional-after-teardown`, `#per-turn-event-log`). Seams: `application-shell/one-board-rendering#one-board-everywhere` is the board this draws through and `live-game-observation/spectator-live-experience` the live surface it must look like; the rows come from the persisted replay, produced by `game-runtime/per-turn-scoreboard#rows-outlive-the-live-audience` — the live observation channel is the parallel consumer of the same rows, never this mode's source, and nothing here recomputes an aggregate
- [ ] 6.5 Board-level mode displays nothing derived from the team action log — no operator selections or shadows, no display-state, worst-case, or heuristic data, for any team including the viewer's own — enforced where the mode binds its data source rather than per component (`replay-and-audit/board-level-replay#no-team-data-in-board-mode`)
- [ ] 6.6 Team-perspective mode as the live operator interface rendered read-only over state reconstructed at the scrubbed moment: every mutating affordance (staging, Drive edits, manual-mode and tempo toggles, boots, submission) absent or disabled while direction preview, worst-case world preview, and decision breakdown stay fully functional; historical selections render as coloured shadows in each operator's live-play colour, and an operator not connected at that moment casts none (`replay-and-audit/team-perspective-replay`, `#live-ui-read-only`, `#shadows-in-original-colours`). Reach "same components, same layout" by mounting the operator surfaces this mode's way rather than by adding a replay branch inside them — the mode and the affordances are mounting parameters the host states (`application-shell/surface-mounting-contract#one-surface-every-mode`, `#the-host-states-what-is-offered`) — so the disabled affordances are presentation and the owning runtimes remain the only thing refusing a write. Seams: `decision-transparency/worst-case-preview` and `decision-breakdown` for the inspection affordances, `operator-control/operator-presence-and-identity#same-colour-on-every-client` for the per-operator colour function (a pure function of game and operator, so the replay recomputes it rather than storing it), `decision-transparency/examined-subject` for the inspection lens those affordances aim, and 5.4 for the connectedness input the shadow rule needs. Source every column of the breakdown from the snapshot being explained and read the team's live portfolio configuration nowhere on this path — the weights and labels are recorded at scoring time, which is what keeps team-perspective replay off a team's private configuration (`decision-transparency/computed-display-state#weights-and-labels-are-recorded-not-joined`, `global-invariants/team-private-centaur-state#finished-games-release-only-what-is-published`)
- [ ] 6.7 Replay visibility bound: team-perspective mode re-applies the viewed team's original invisibility filter at the scrubbed moment as a presentation projection over the full persisted record, so an opponent snake invisible to the team then stays elided there, while the same viewer switching to board-level mode sees it (`replay-and-audit/replay-visibility-bound`, `#invisible-then-invisible-now`, `#board-mode-tells-the-whole-truth`). Seam: `live-game-observation/invisibility-filtering` owns the rule being replayed; record that re-applying it here is fidelity to the lived view, not continued secrecy, and therefore is not an enforcement point
- [ ] 6.8 One timeline control governing both modes: play, pause, scrubber, a playback-speed control labelled in the active mode's unit, and a scrub-mode toggle defaulting to Per-Turn; Per-Turn shows turns as equidistant ticks, snaps only to end-of-turn states, and plays in turns per second; Timeline puts the axis on the game's real wall-clock span with proportional spacing, scrubs continuously in clock time, and plays at multiples of real time; keyboard scrubbing matches the active mode's granularity; mode and speed are client-local and never persisted to the platform (`replay-and-audit/unified-timeline`, `#snap-to-what-the-team-saw`, `#unequal-turns-render-unequal`, `#mode-and-speed-are-local`). Place each turn's boundary marker by one rule with no gaps: the latest declaration timestamp the record holds for the turn when every team's declaration for it was stamped, and the turn's recorded resolution start otherwise — the record stamps only explicit declarations, so a turn ended by clock expiry or by a snakeless team takes the resolution start and is never left unplaceable (`replay-and-audit/unified-timeline#a-turn-nobody-declared-is-still-placed`, `game-runtime/turn-declaration#expiry-detected-autonomously`, `#snakeless-team-never-blocks`, `game-runtime/turn-keyed-game-record#resolution-takes-time` for the fallback's clock)
- [ ] 6.9 Replay inspection on top of the platform's inspection lens, not a second one: reuse `decision-transparency/examined-subject` — client-local, never persisted, independent of holding, staging nothing — and implement only what replay adds, namely that the subject is free of the game's history (any snake on the viewed team at any scrubbed moment, whoever held it then) and that the reconstructed selection shadows keep rendering unchanged beside it, with a test that concurrent viewers of the same game inspecting different snakes share no state (`replay-and-audit/replay-inspection`, `#concurrent-inspectors-never-conflict`, `#inspect-regardless-of-history`, `#shadows-unaffected`, `decision-transparency/examined-subject#never-persisted`)
