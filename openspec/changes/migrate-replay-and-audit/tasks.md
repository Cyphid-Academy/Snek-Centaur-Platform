- [ ] 1.3 Extract the recorded-run codec and replay-check into a shared package, then build this capability's record on it. `test-sequences/canonical-encoding`, `test-sequences/replay-check` and `test-sequences/determinism#production-seed-derivation` are folded into `openspec/specs/` already but implemented app-locally in `apps/visual-tester/src/lib/test-sequences/`; this capability now declares `test-sequences` and reuses them rather than shipping a second encoding (`game-runtime/replay-sufficiency`, `#one-canonical-encoding`, `#bit-identical-reproduction`). Move the canonical JSON codec, the turn-seed derivation, and the halt-at-first-divergence comparison into a package that both `packages/stdb`'s record path and `apps/visual-tester` consume — the capability's Purpose already anticipates a headless consumer — and leave no second encoding of any engine value behind, in particular no row-oriented shape with JSON-string bodies

## 2. In-instance game record (SpacetimeDB — `packages/stdb`)

- [ ] 2.1 Turn-keyed append-only historical tables, written only by the resolving transaction (and by initialization for the turn-0 rows): per-snake full-state snapshots at each turn boundary, item lifetimes as spawn/destroyed-turn pairs with start-of-game items at spawn turn 0, the board layout written once at initialization, per-team post-turn budget with declaration kind and the timestamp for explicit declarations, each turn's wall-clock start and resolution-start, every turn event attributed to its turn, and no cap, eviction, or windowing anywhere in the retention path (`game-runtime/turn-keyed-game-record`, `#items-derivable-at-any-turn`, `#resolution-takes-time`, `#unbounded-retention`). Include each completed turn's per-team aggregate rows among those tables — write them as durable record rows in the same transaction that commits the turn, never as a projection assembled for a live subscription, so a historical figure can never disagree with the one published live (`game-runtime/turn-keyed-game-record#aggregates-are-recorded-not-recomputed`; seam: `live-game-observation/scoreboard-sole-aggregate-authority` produces them and `#rows-outlive-the-live-audience` pins their durability)
- [ ] 2.2 Append-only enforcement inside the instance: no update or delete path exists for a committed record row or event, the item destroyed-turn stamp is the single permitted touch of a written row and fires exactly once from empty, and a past turn reads identically before and after later turns commit — tested by reading an early turn at two points in a long game (`replay-and-audit/append-only-history`, `#no-retroactive-correction`, `#past-reads-stable`, `#the-single-stamp`)
- [ ] 2.3 Turn-event rows over the record's closed vocabulary — exactly the shared engine's event union, neither narrowed nor extended — each row carrying enough payload to visualise its outcome without re-executing resolution or diffing snapshots, and death events stating cause, contributing damage sources, and responsible snake (`game-runtime/turn-event-record`, `#death-carries-its-cause`, `#hazard-damage-never-double-counted`, `#no-new-kinds-by-extension`). The hazard-damage kind is the engine's, not an instance-side addendum: `game-engine/turn-events` now carries it (added by the `revise-game-engine-contract` change, because the engine already applies the damage in `health-and-starvation` and deriving it instance-side from committed state, hazard tiles, and configured damage would be a second implementation of that rule), so the record stores it like any other kind and adds none of its own — do not reintroduce a record-local hazard event (`game-engine/turn-events#hazard-damage-is-announced`; seam: `revise-game-engine-contract` must land first)
- [ ] 2.4 Canonical representation order as a pure derivation over event data (event-type class, then subject identifier, then a payload tie-break) with no stored sequence column, placed in a module both the instance and the replay client consume — `live-game-observation/observation-use-cases#canonical-order-is-read-not-delivered` points live consumers at the same derivation, so a private copy per runtime would drift; property-test order stability across independent runs of the same game and bit-exact record-to-record comparison (`game-runtime/canonical-event-order`, `#derived-not-stored`, `#stable-across-replays`, `#order-implies-no-causality`)
- [ ] 2.5 Replay-sufficiency verification: reconstruct every board state, item lifetime, turn event, and staged-move attribution from the record's rows alone with no rule re-execution and no other runtime consulted, and encode the record's engine values with the shared canonical codec from 1.3 so record-to-record comparison is defined over one encoding (`game-runtime/replay-sufficiency`, `#nothing-else-consulted`, `#one-canonical-encoding`). Build the determinism test by feeding two records of a game re-run from the same seed, configuration, and staged-move sequence through the existing recorded-run replay-check rather than writing a comparison harness for replays alone (`game-runtime/replay-sufficiency#bit-identical-reproduction`, `test-sequences/replay-check#halt-at-first-divergence`, `test-sequences/canonical-encoding#equal-values-equal-json`). Confirm the record carries the runtime configuration as well as the seed — the requirement names configuration among determinism's inputs while only `once-at-end-export` pins an artefact (the seed) that must travel

## 3. Attribution, from admission to persisted fact (`packages/stdb`, checked in `packages/convex-host`)

- [ ] 3.1 Connection-admission attribution: resolve every admitted connection to an agent value at the moment of admission — the team identity for a bot connection, the operator's identity for an operator connection — retain one entry per admitted connection for the instance's whole life, carry the value untouched wherever the connection's actions are recorded, and never mutate or delete an entry: disconnection writes nothing and a reconnect appends a fresh entry (`game-runtime/connect-time-attribution`, `#resolved-at-connect-never-later`, `#disconnect-erases-nothing`, `#reconnect-appends-fresh`). Seam: `identity-and-authorization/admission-validation` and `game-token-contents` decide what the connection presents; `admission-records-private` keeps these entries off every client surface
- [ ] 3.2 Staged-move and movement attribution: every staged-move log entry permanently records the writing agent, the wall-clock time it was accepted, and the turn it was staged in, including superseded entries; a movement event carries the agent whose staged move resolution consumed and carries none exactly when the move came from the engine's fallback, with no sentinel value and no split event kind (`game-runtime/staged-move-attribution`, `#sub-turn-staging-history`, `#bot-and-operator-distinguishable`, `#fallback-moves-attributed-to-no-one`). Seam: the log itself is `game-runtime/staged-move-log`; this capability adds only the permanence and attribution of its entries
- [ ] 3.3 Agent-form persistence: the Convex-side persistence path verifies, as a defensive check before writing, that every attribution in the record is in agent form and surfaces a non-conforming record as a defect rather than persisting it; persisted attribution is bound to the game's roster snapshot so later roster edits, team archival, or account changes never rewrite who did what — tested with a member removed after the game finished (`replay-and-audit/agent-form-persistence`, `#defensive-check-at-persistence`, `#removed-member-still-attributed`). Seam: `identity-and-authorization/roster-snapshot-binding` and `game-lifecycle/roster-snapshot` own the snapshot this binds to

## 4. Once-at-end export and replay persistence (`packages/stdb` export path, `packages/convex-host` + `packages/convex-snek-platform`)

- [ ] 4.1 The single sanctioned egress: bundle the complete record into the terminal notification exactly once at game end, with no incremental, per-turn, or partial export path existing anywhere for any part of it; every accumulated part travels — each completed turn's per-team aggregate rows, the full staged-move log, and the attribution records — and visibility filtering is bypassed so invisible snakes' states are included; the per-game seed travels in the export though no game client can observe it while the game runs; an error outcome bundles no replay data (`replay-and-audit/once-at-end-export`, `#nothing-leaves-per-turn`, `#filter-bypassed-for-export`, `#aggregates-travel-with-the-record`, `#seed-secret-live-exported-post`, `#error-outcome-exports-nothing`). Seam: `game-lifecycle/finish-notification` owns the notification, its credential, and the no-scores half of error handling
- [ ] 4.2 Platform-only retrieval: the export is reachable only under the platform's own privilege, distinct from every gameplay admission, and no operator, bot, spectator, or coach connection can retrieve it — which rests on the instance's client read surface being filtered views only, with the raw record and attribution tables outside it (`replay-and-audit/once-at-end-export#platform-only-retrieval`). Seam: `live-game-observation/filtered-views-are-the-only-surface` and `identity-and-authorization/admission-records-private` are what make a per-role check list unnecessary
- [ ] 4.3 Persist the exported record as the game's replay bound to its persistent game record, starting only after the instance has signalled its terminal state and completing before teardown; no path begins persistence for a game still in play (`replay-and-audit/replay-persistence`, `#not-before-terminal-signal`). Name the seam precisely in the code and in `// spec:` citations: this capability owns **record sufficiency** — what the persisted record must contain and the shape of the bundled replay data, including its absence on error outcomes — while `game-lifecycle/teardown-after-persistence` owns only the bracket that keeps the instance alive until persistence is confirmed, and `game-lifecycle/game-record` the record the replay binds to
- [ ] 4.4 Post-teardown permanence: the persisted replay and the game's team-experience records — the action log and the display-state snapshots — survive teardown for the life of the game record, teardown cascades into none of them, and no code path from replay viewing reaches for a game instance (`replay-and-audit/replay-persistence#viewing-never-consults-an-instance`, `#team-experience-outlives-teardown`). Confirm what "display-state snapshots" resolves to: `decision-transparency/snapshot-full-replacement` keeps only the latest published snapshot per snake, so the *history* the reconstruction guarantee needs is the action log's snapshot entries, not that record

## 5. Team action log and experience reconstruction (Convex — `packages/convex-centaur-state`, writers in `packages/convex-host`, `packages/centaur-server-lib`, `apps/centaur-server-reference`)

- [ ] 5.1 Per-game team action log at sub-turn wall-clock resolution: every entry carries the game, the turn, the acting identity and its kind (operator, or the team's server acting as its bot), and a wall-clock timestamp; the category set covers operator arrivals and departures (the departure carrying its cause — deliberate leave, lost connection, or Captain boot), snake selection and deselection, manual-mode toggles, Drive addition and removal, heuristic weight and activation changes carrying both old and new values, temperature-override changes, per-operator tempo changes, Captain boots, team-side turn submissions, and computed-display-state snapshots — with no move-staging category, since staged moves live solely in the instance's log; entries have no edit or delete mutation at all (`replay-and-audit/team-action-log`, `#sub-turn-resolution`, `#tempo-and-boot-are-clock-anchored`, `#every-departure-is-logged-however-it-happened`, `#weight-change-carries-before-and-after`, `#move-staging-excluded`, `replay-and-audit/append-only-history#action-log-entries-never-corrected`). Fix each category's entry payload so the entry is self-sufficient evidence of its own transition — in particular the snapshot category carries the full published snapshot, which the requirement's minimum field list does not state
- [ ] 5.2 Writer discipline and transactional pairing at the Convex mutation contract: each entry is written by the actor it describes under that actor's own credential, the team's hosting server writes the snapshot category exclusively and every published snapshot produces its entry, every mutation of recorded team state writes its entry in the same transaction as the mutation, and no back-fill or reconciliation path exists that could supply an entry an actor's own write did not produce (`replay-and-audit/actors-write-own-entries`, `#dropped-entry-means-no-mutation`, `#server-never-ghost-writes`, `#every-snapshot-logged`). Implement the single exemption explicitly and in one place — the departure entry, written by Convex itself as it observes the operator's coordination connection end, since no departing client can be relied on to write it (`replay-and-audit/actors-write-own-entries#the-one-entry-its-actor-cannot-write`). Seams: `decision-transparency/hosting-server-sole-writer` for snapshot writership, `operator-control` and `turn-pacing` for the mutations whose transactions these entries join
- [ ] 5.3 Experience-reconstruction query over the persisted replay plus the action log, answering at any wall-clock moment — inside a turn, not only at boundaries — each operator's selected snake, each snake's manual-mode flag, active Drives with targets and weights, heuristic activations and weight overrides, temperature override, display state as last written before that moment, the staged moves and who staged them (read from the game record), and the active-operator set with each operator's tempo, folded from the log's own arrival and departure entries; with guard-rail tests that board contents, snake bodies, and outcomes are never derived from the log, and that presence is never inferred from a lull in an operator's activity (`replay-and-audit/experience-reconstruction`, `#any-moment-not-just-boundaries`, `#selection-history-from-the-log-alone`, `#presence-is-read-not-guessed`, `#board-truth-from-the-game-record-only`)
- [ ] 5.4 Connection events in Convex — the producer 5.3 and the shadow rule both read. On an operator joining the team's game session, write an arrival entry from that operator's own credentialed client, in the same transaction as the tempo write `turn-pacing/operator-tempo#flow-on-every-rejoin` already performs; on that operator's Convex coordination connection ending, write a departure entry from Convex itself, carrying whether it was a deliberate leave, a lost connection, or a Captain's boot. Convex is the writer because the log is Centaur state and the game instance may not egress mid-game; a Captain boot therefore produces two entries — the Captain's own boot entry and the booted operator's departure entry — which must not be conflated (`replay-and-audit/team-action-log#every-departure-is-logged-however-it-happened`, `replay-and-audit/actors-write-own-entries#the-one-entry-its-actor-cannot-write`, `replay-and-audit/experience-reconstruction#presence-is-read-not-guessed`, `replay-and-audit/team-perspective-replay#shadows-in-original-colours`). Seams: `operator-control/operator-dual-connection` owns the connection whose lifetime is observed, `operator-control/captain-boot` the boot that severs it, `global-invariants/game-instance-hermeticity#no-egress-before-game-end` the reason the instance cannot be the writer. Settle the liveness the connection layer must give Convex — how promptly a dropped connection is observed, and that a drop is eventually recorded rather than silently lost — since the reconstruction's accuracy is bounded by it

## 6. Replay surface: discovery, viewer, modes, timeline (`apps/centaur-server-reference` + `packages/centaur-server-lib`, reading `packages/convex-snek-platform`)

- [ ] 6.1 Finished-game readability and the one viewer's gate: a finished game's full record — board-level replay plus every participating team's action-log entries, display-state snapshots, and staged-move history — is readable by every authenticated user; one unified viewer serves every entry point with board-level and team-perspective as modes rather than separate applications; it opens only for a finished game with a persisted replay (so an error outcome opens nothing); a game still in play is refused by the replay surface entirely; and a direct-link affordance produces a URL that takes any authenticated user to that game's replay (`replay-and-audit/finished-games-public`, `#finished-means-open`, `#direct-link-grants-any-finished-replay`, `#live-games-not-on-the-replay-surface`, `replay-and-audit/unified-replay-viewer`, `#one-viewer-not-two`, `#finished-with-replay-only`, `#team-perspective-participants-only`)
- [ ] 6.2 Per-hosted-team game-history listing: completed games in reverse chronological order, listed for a user exactly when they were a member at the time of the game per the roster snapshot or are a current member, showing room, date, opposing teams, the team's result, the normalised score as the headline value against par 1.0 in real-valued display, and aggregate body length as the secondary stat; selecting a listing opens the viewer defaulting to team perspective (`replay-and-audit/team-game-history`, `#historical-or-current-membership`, `#listing-is-discovery-not-access`, `#normalised-score-headline`). Seams: `game-lifecycle/roster-snapshot` for membership-at-the-time, `game-lifecycle/game-record` for the outcome and timestamps, `rooms-and-matchmaking` for the room. Confirm where aggregate length comes from — the recorded outcome carries scores, so the secondary stat plausibly requires the replay's final scoreboard row, which a cheap listing query should not have to open
- [ ] 6.3 Replay data binding with no mutation surface at all — mutation is structurally absent rather than present and refused, so no invocable write exists for a replay client and no runtime guard stands between a viewer and a write; interface components get their read-only behaviour from the binding, never from a per-component replay branch (`replay-and-audit/replay-binding-mutation-free`, `#absence-not-guard`, `#read-only-is-not-per-component`). Record in code comments that this is an architecture property, not a security boundary — enforcement stays with the owning runtimes per `global-invariants/security-enforced-outside-the-library`
- [ ] 6.4 Board-level mode sourced from the persisted replay alone, functional long after teardown: board terrain, snakes, items, hazards, and fertile tiles at the selected turn; the per-team scoreboard with normalised score as headline at par 1.0 and aggregate length secondary, from the recorded rows; and a per-turn event log listing the turn's events from the closed enumeration with no kind unrepresentable, visually consistent with live spectating (`replay-and-audit/board-level-replay`, `#functional-after-teardown`, `#per-turn-event-log`). Seams: `live-game-observation/spectator-live-experience` for the shared renderer, `scoreboard-sole-aggregate-authority` for the rows
- [ ] 6.5 Board-level mode displays nothing derived from the team action log — no operator selections or shadows, no display-state, worst-case, or heuristic data, for any team including the viewer's own — enforced where the mode binds its data source rather than per component (`replay-and-audit/board-level-replay#no-team-data-in-board-mode`)
- [ ] 6.6 Team-perspective mode as the live operator interface rendered read-only over state reconstructed at the scrubbed moment: every mutating affordance (staging, Drive edits, manual-mode and tempo toggles, boots, submission) absent or disabled while direction preview, worst-case world preview, and decision breakdown stay fully functional; historical selections render as coloured shadows in each operator's live-play colour, and an operator not connected at that moment casts none (`replay-and-audit/team-perspective-replay`, `#live-ui-read-only`, `#shadows-in-original-colours`). Seams: `decision-transparency/worst-case-preview` and `decision-breakdown` for the inspection affordances, `operator-control/operator-presence-and-identity#same-colour-on-every-client` for the per-operator colour function (a pure function of game and operator, so the replay recomputes it rather than storing it), `decision-transparency/examined-subject` for the inspection lens those affordances aim, and 5.4 for the connectedness input the shadow rule needs. Source every column of the breakdown from the snapshot being explained and read the team's live portfolio configuration nowhere on this path — the weights and labels are recorded at scoring time, which is what keeps team-perspective replay off a team's private configuration (`decision-transparency/computed-display-state#weights-and-labels-are-recorded-not-joined`, `global-invariants/team-private-centaur-state#finished-games-release-only-what-is-published`)
- [ ] 6.7 Replay visibility bound: team-perspective mode re-applies the viewed team's original invisibility filter at the scrubbed moment as a presentation projection over the full persisted record, so an opponent snake invisible to the team then stays elided there, while the same viewer switching to board-level mode sees it (`replay-and-audit/replay-visibility-bound`, `#invisible-then-invisible-now`, `#board-mode-tells-the-whole-truth`). Seam: `live-game-observation/invisibility-filtering` owns the rule being replayed; record that re-applying it here is fidelity to the lived view, not continued secrecy, and therefore is not an enforcement point
- [ ] 6.8 One timeline control governing both modes: play, pause, scrubber, a playback-speed control labelled in the active mode's unit, and a scrub-mode toggle defaulting to Per-Turn; Per-Turn shows turns as equidistant ticks, snaps only to end-of-turn states, and plays in turns per second; Timeline puts the axis on the game's real wall-clock span with proportional spacing, scrubs continuously in clock time, and plays at multiples of real time; keyboard scrubbing matches the active mode's granularity; mode and speed are client-local and never persisted to the platform (`replay-and-audit/unified-timeline`, `#snap-to-what-the-team-saw`, `#unequal-turns-render-unequal`, `#mode-and-speed-are-local`). Place each turn's boundary marker by one rule with no gaps: the latest declaration timestamp the record holds for the turn when every team's declaration for it was stamped, and the turn's recorded resolution start otherwise — the record stamps only explicit declarations, so a turn ended by clock expiry or by a snakeless team takes the resolution start and is never left unplaceable (`replay-and-audit/unified-timeline#a-turn-nobody-declared-is-still-placed`, `game-runtime/turn-declaration#expiry-detected-autonomously`, `#snakeless-team-never-blocks`)
- [ ] 6.9 Replay inspection on top of the platform's inspection lens, not a second one: reuse `decision-transparency/examined-subject` — client-local, never persisted, independent of holding, staging nothing — and implement only what replay adds, namely that the subject is free of the game's history (any snake on the viewed team at any scrubbed moment, whoever held it then) and that the reconstructed selection shadows keep rendering unchanged beside it, with a test that concurrent viewers of the same game inspecting different snakes share no state (`replay-and-audit/replay-inspection`, `#concurrent-inspectors-never-conflict`, `#inspect-regardless-of-history`, `#shadows-unaffected`, `decision-transparency/examined-subject#never-persisted`)
