## 2. The filtered read surface (`packages/stdb/`)

- [ ] 2.1 Establish the view-mediated read surface: every client-subscribable read of a live game is a purpose-built server-side filtered view over the turn-keyed tables, no raw-table subscription path exists for any client connection, and adding a new observable datum means adding a view rather than opening a table (live-game-observation/filtered-views-are-the-only-surface, #new-read-surfaces-are-views); make the admission/attribution record non-subscribable as part of the same surface — seams: identity-and-authorization/admission-records-private owns that record's privacy, global-invariants/state-confined-to-owning-runtime#convex-never-mirrors-a-live-game owns the completeness claim
- [ ] 2.2 Implement the invisibility filter inside the snake-state view: team-granular on the connection's validated team binding, a connection bound to no team therefore filtered as an opponent of every team (intersection, never union), own-team connections receiving their invisible snakes with visibility state exposed, and item, event, board and roster channels left unfiltered so board effects stay observable including at turn 0 (live-game-observation/invisibility-filtering, #spectators-are-opponents-of-every-team, #ally-sees-visible-false, #board-effects-stay-observable, #turn-zero-is-public) — seams: game-engine/invisibility owns the derivation, global-invariants/team-granularity-authorization#spectators-hold-no-private-state owns the reader partition
- [ ] 2.3 Filter on visibility as recorded at the observed turn, transitioning exactly at turn boundaries, with historical reads evaluated on the identical predicate so no scrub can recover a snake hidden at that turn (live-game-observation/visibility-transitions-and-history, #vanishes-and-reappears-at-boundaries, #history-scrub-cannot-reveal)
- [ ] 2.4 Serve per-turn reconstruction from the views alone — every observable snake's boundary state, the items then on the board, each team's remaining budget, and the turn's full event list — with no rule re-execution and no derivation from earlier turns (live-game-observation/historical-reconstruction, #no-rules-re-execution, #reconstruction-respects-visibility); seams: game-runtime/turn-keyed-game-record and replay-and-audit/append-only-history own the record being read, game-runtime/in-game-clock owns the per-turn budget records, game-engine/chess-timer the arithmetic
- [ ] 2.5 Reconcile the vocabulary drift against existing code: `packages/stdb/AGENTS.md` and the `// spec:` header in `packages/stdb/src/index.ts` describe the mechanism as "row-level security rules for snake invisibility" (and global-invariants/security-enforced-outside-the-library names row-level security), while this capability and the legacy Design mandate purpose-built server-side *views* — settle one name and sweep the package's agent context and citations (live-game-observation/filtered-views-are-the-only-surface, #raw-protocol-client-gets-filtered-data)

- [ ] 2.6 Team-scoped staged-move view: a team's connections read the complete multi-turn staged-move history the instance's log holds for them, superseded entries included, while a connection bound to another team or to none — opposing operator, spectator, opposing coach — reads none of it at any turn, before or after resolution; enforced in the view predicate alongside every other visibility rule, never by a client-side filter (live-game-observation/staged-move-privacy, #own-history-complete, #cross-team-never-even-after-resolution) — seams: game-runtime/staged-move-log owns the log this view reads and game-runtime/staged-move-attribution the per-entry writer it must not leak across teams, global-invariants/team-granularity-authorization#spectators-hold-no-private-state owns the reader partition, operator-control/board-and-move-interface is the own-team consumer whose staged-move markers this view feeds

## 3. Real-time committed delivery (`packages/stdb/` + client subscription helpers)

- [ ] 3.1 Deliver committed state by push on commit: a subscribed connection observes each turn's outcome as it lands, with no timer-driven re-query anywhere in the read path (live-game-observation/real-time-committed-delivery, #no-polling); keep the wire transport, channel implementation and reconnection mechanics as code-level mechanism per this change's transport-neutrality decision
- [ ] 3.2 Make a committed turn observable as exactly one atomic logical update — no torn combination of a turn's snake states, events, items or scoreboard, and no intermediate resolution-pipeline state ever observable (live-game-observation/real-time-committed-delivery, #snapshot-and-events-arrive-together, #no-partial-resolution-state); seam: the all-or-nothing commit itself is global-invariants/authoritative-turn-resolution#turn-resolution-is-atomic realised by game-runtime/exactly-once-resolution — this task implements only the observation-side consequence
- [ ] 3.3 Implement the four observation use cases as concrete subscription patterns over the views — live current-turn view, point-in-time observation of any completed turn, turn-transition observation (the new state together with the events that produced it) sufficient to animate, and mid-game catch-up delivering the full history so far then incremental updates with no gap at the join (live-game-observation/observation-use-cases, #mid-game-join)
- [ ] 3.4 Guarantee no delivery-order contract and make consumers order a turn's events by the stored record's canonical representation order rather than by arrival, including in whatever client helper wraps the subscription (live-game-observation/observation-use-cases#canonical-order-is-read-not-delivered); seam: game-runtime/canonical-event-order owns the derivation rule — this capability must neither store nor deliver an ordering datum of its own

## 4. Scoreboard delivery (`packages/stdb/`)

- [ ] 4.1 Expose the per-turn aggregate rows through the same view surface as everything else, identical for every connection, carrying per-team aggregates only with no per-snake state, delivered whenever the turn they summarise is observable, and give clients no second channel for any team-level aggregate (live-game-observation/scoreboard-sole-aggregate-authority, live-game-observation/scoreboard-sole-aggregate-authority#client-aggregation-is-a-defect, live-game-observation/scoreboard-sole-aggregate-authority#never-lags-the-snapshot); seam: writing the rows is game-runtime/per-turn-scoreboard's — this capability neither computes an aggregate nor re-derives one
- [ ] 4.2 Verify the bounded-disclosure boundary the rows sit on: an invisible snake contributes to its team's delivered aggregates while its own state stays filtered out of every non-allied delivery, and no consumer can invert the aggregate to recover the hidden snake (live-game-observation/scoreboard-sole-aggregate-authority#invisible-snakes-counted-not-revealed, live-game-observation/invisibility-filtering)

## 5. Team-private live state and the coach read scope (`packages/stdb/`, `packages/convex-centaur-state/`, `packages/convex-host/`)

- [ ] 5.1 Admit a coach connection to exactly the member's filtered terms on the instance side — the same team binding in every view predicate, nothing added and nothing withheld — and confer no read privilege from any platform-side standing (live-game-observation/team-private-live-state, #coach-parity-with-members); seams: identity-and-authorization/coach-tokens and identity-and-authorization/role-bound-privileges own the credential and the mutation refusal, identity-and-authorization/platform-admin-role owns admins as implicit coaches
- [ ] 5.2 Enforce the Convex half of the private observation context: the team-scoped working state the platform holds around a team's live play is readable only by that team's members, its designated coaches, and platform admins, refused across teams, and enforced at the Centaur subsystem's own function contract so no surface widens it (live-game-observation/team-private-live-state, #cross-team-reads-denied); seams: global-invariants/team-private-centaur-state owns the rule and locates this half of enforcement in Convex rather than in the instance's views, decision-transparency/computed-display-state owns the recorded deliberation this read scope actually protects, team-management/coaches owns designation
- [ ] 5.3 Pin the live/post-game visibility boundary at the game's finish and verify the two sides do not contradict: coach standing must add nothing once a game is finished, the live observation surfaces must stop observing at that moment, and the post-game record deliberately reveals what the live filter hid (live-game-observation/team-private-live-state#finished-games-owe-coaches-nothing, live-game-observation/spectator-access#session-ends-cleanly); seams: replay-and-audit/finished-games-public and replay-and-audit/replay-visibility-bound own the post-game terms, game-lifecycle/status-authority owns the status transition

## 6. Client observation surfaces (`apps/centaur-server-reference/`, `packages/centaur-server-lib/`)

- [ ] 6.1 Add a spectator read binding to the data-source abstraction in `packages/centaur-server-lib/` whose mutation surface is absent at the type level, so read-only is a structural property rather than a set of disabled controls (live-game-observation/spectator-live-experience#zero-mutating-affordances); note for the author that the abstraction itself carries no owning requirement (its legacy ids are dispositioned as code mechanism) and that the legacy contract enumerates live, replay and coach bindings but never a spectator one — this binding is new surface
- [ ] 6.2 Build the spectating route: obtain a spectator access token through the platform's issuance path on entry, connect read-only under it, and on navigating away or the game finishing release the subscription and discard the token so nothing retained continues to observe or authenticate (live-game-observation/spectator-access, #entry-obtains-a-token, #session-ends-cleanly); gate entry on authentication and the game being in play and nothing narrower, recording the deliberate deferral in code so no ad-hoc restriction or rate limit drifts in (#eligibility-deliberately-open); seams: identity-and-authorization/spectator-tokens, identity-and-authorization/client-credential-custody, identity-and-authorization/live-game-issuance
- [ ] 6.3 Render the live spectating view from the filtered subscription in real time — board terrain, items, observable snakes, turn events, the current turn number, and per participating team the remaining time budget and declared-turn-over status (live-game-observation/spectator-live-experience, #pacing-legible-without-private-state); seams: game-runtime/in-game-clock and game-runtime/turn-declaration own the pacing data, game-engine/chess-timer the budget semantics
- [ ] 6.4 Implement the spectator timeline: subscribe to the game's full history up-front on entry (accepting entry latency bounded by game length, with no lazy fetch and no prefetch window), scrub over every completed turn reconstructing board, snakes, items, scoreboard and events without interrupting the live feed, show a visible not-live indication while scrubbed, and offer a one-action return to the live head (live-game-observation/spectator-timeline, #upfront-history-no-lazy-fetch, #scrub-while-live-continues)
- [ ] 6.5 Link to a playing game's spectating view from its room's lobby (live-game-observation/spectator-access#reachable-from-the-lobby) — seam: rooms-and-matchmaking/room-lobby owns the lobby view itself and states no spectating link, so agree with that capability's implementer where the link lives rather than duplicating lobby content here
- [ ] 6.6 Make every observation surface honour the filter rather than re-deriving it: never infer, reconstruct or approximate hidden snake state from events, aggregates or gaps in deliveries, and render invisibility indication only for own-team snakes from the delivered visibility state (live-game-observation/ui-honours-the-filter, #never-infers-hidden-state, #own-team-indication-only); seam: global-invariants/client-truthfulness owns the general posture, and because this code ships in a forkable app the obligation is honouring only — no visibility enforcement may relocate here
- [ ] 6.7 Build coach mode into a team's live interface, reachable from wherever that team's live game is surfaced including its spectating view: the full member interface with every writing affordance — selection, staging, configuration edits, pacing, team controls — disabled or absent and the mode visibly read-only, with a coach's inspection rendering alongside the operators' real selection shadows rather than in place of them and reading — in gesture and on the board — as visibly not a hold (live-game-observation/coach-mode-interface, #every-mutating-affordance-inert, #inspection-is-client-local, #inspection-never-reads-as-selection); seams: operator-control/exclusive-selection and operator-control/board-and-move-interface own the selection state and the interface being mirrored, decision-transparency owns the team-private panels it renders
- [ ] 6.8 Reuse the platform's inspection lens in coach mode rather than building a second one: the client-local, never-persisted examination selection that is independent of holding and stages nothing is decision-transparency/examined-subject, and coach mode is one of its clients. This capability deliberately does not declare that dependency — the edge would close a cycle through operator-control — so the reuse is code-level only: implement no coach-local copy of the lens, and add no restatement of its properties back into this capability's spec (live-game-observation/coach-mode-interface#inspection-is-client-local, decision-transparency/examined-subject#examining-is-not-acting, decision-transparency/examined-subject#never-persisted)
