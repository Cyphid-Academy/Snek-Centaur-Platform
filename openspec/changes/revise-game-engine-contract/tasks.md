## 2. The state shape: turns at two grains (`packages/engine/`)

- [ ] 2.1 Add the per-snake turn and the state's current turn to the game-state vocabulary, the latter defined as the greatest turn any snake has reached rather than stored independently — so it cannot disagree with the snakes it summarises, and holding everything is a no-op by construction. Keep turns absolute rather than staleness counters, so staleness stays a subtraction against whichever turn a consumer is asking about (game-engine/domain-vocabulary, `#turns-at-two-grains`)
- [ ] 2.2 Provide the narrowing from a partial state to a game state — total when every alive snake's turn equals the state's, absent otherwise — and make it the only way to obtain the persisted form, so a caller that held anything cannot produce it (game-engine/domain-vocabulary#lockstep-is-the-game-state-invariant)
- [ ] 2.3 Remove `turnNumber` from the resolution signature now that the state carries it, and have an advanced state carry the turn it advanced to. Sweep every caller across the workspace (game-engine/turn-resolution-model)
- [ ] 2.4 Widen the consumer-facing helpers that take a game state to accept the partial form, `isValidMove` first — heuristics run over partial boards, so a helper that only accepts the lockstep form is unusable in the search it exists to serve (game-engine/domain-vocabulary)

## 3. Two entry points over one stage list (`packages/engine/`)

- [ ] 3.1 Factor direction resolution out of the turn context so it belongs to advancing a turn rather than to imagining moves: staged move, else `lastDirection`, else the turn-0 seeded pick. Imagining moves receives explicit directions only and performs no fallback (game-engine/movement, `#fallback-belongs-to-advancing-a-turn`)
- [ ] 3.2 Expose imagining moves over a partial state — a caller-chosen set of snakes advanced with explicit directions, the rest held — running move projection, head-to-head precedence, interaction rules, derived rules and commit, and returning a partial state with its events (game-engine/turn-resolution-model, `#imagining-moves-yields-a-partial-state`)
- [ ] 3.3 Gate item spawning and the win check on one condition about the state — every alive snake at its current turn — independent of which entry point was called and of whether a seed was supplied. Imagining moves accepts a seed and uses it only where a stage that runs needs one, so seeded work over mixed-turn boards stays open to us later rather than being designed out (game-engine/turn-resolution-model#spawning-and-outcome-need-lockstep)
- [ ] 3.4 Define advancing a turn in terms of imagining moves: resolve directions, imagine them with nothing held, spawn, check the outcome, narrow. Pin the equivalence with a property test — advancing a turn and imagining the same complete move set produce identical states and events (game-engine/turn-resolution-model#advancing-is-imagining-with-nothing-held)

## 4. What holding means (`packages/engine/`)

- [ ] 4.1 Separate the context's *participants* (alive and taking the turn) from the snakes *present* (all alive): participants drive projection, surviving heads, the health tick and health resolution, while present snakes drive occupancy — and effect expiry, which runs for everyone against the state's current turn (game-engine/held-snakes, `#a-hold-suspends-the-snakes-own-turn`, `#timers-do-not-pause-for-a-hold`)
- [ ] 4.2 Enter held bodies into the body-collision index **from index 0**, since a held snake's head is a stationary occupied cell — the index skips index 0 today because in lockstep a head is only ever contested through head-to-head (game-engine/held-snakes#a-held-body-is-an-obstacle-including-its-head)
- [ ] 4.3 Exclude held snakes from head-to-head precedence entirely, so a mover entering a held snake's head cell dies by body collision rather than losing or winning a contest with something that never moved (game-engine/held-snakes#a-held-snake-contests-nothing)
- [ ] 4.4 Keep effect expiry running for held snakes, against the state's current turn — an expiry turn is fixed when the effect is granted and no choice the snake makes moves it, so withholding it would invent certainty rather than model uncertainty. Withhold the health tick and health resolution instead, since a snake allowed to move might have reached food. Test both sides of the line together, because they look inconsistent until the reason is visible (game-engine/held-snakes#timers-do-not-pause-for-a-hold, `#a-hold-suspends-the-snakes-own-turn`)
- [ ] 4.5 Apply another snake's action to a held snake where the rules say so — a potion collector's teammates receive their buffs whether or not they moved, and the collection event's affected-teammate list is unchanged by holding (game-engine/held-snakes#a-hold-does-not-shield-the-snake, game-engine/team-potion-effects#sacrificial-collection)
- [ ] 4.6 Emit no movement event for a held snake, and confirm the event set stays sufficient to reconstruct the resolution for a consumer reading events alone (game-engine/held-snakes, game-engine/turn-events)
- [ ] 4.7 Adversarial tests for the cases where holding-as-input and holding-as-post-processing diverge — a mover entering the cell a held snake's head would have vacated, and a held body severing a mover that would have passed through vacated space. Cover the tail case separately and state its reason in the test name: following a held tail is a legal follow in lockstep and a collision here, not merely because the snake did not move but because a simulated snake reaching food would have kept that segment anyway (game-engine/held-snakes#holding-is-an-input-not-a-correction, `#a-held-tail-is-impassable`, game-engine/collisions-and-severing)

## 5. Refusing rather than guessing (`packages/engine/`)

- [ ] 5.1 Return a failure, never a state, when an alive snake is neither given a direction nor held — no `lastDirection` fallback reaches a hypothetical, which is the whole point of the entry-point split (game-engine/hypothetical-resolution-failure#every-snake-needs-a-disposition)
- [ ] 5.2 Return a failure when asked to advance a snake whose turn is behind the state's: only held snakes may lag. Record in the failure why the fence exists, so the message survives the fence being relaxed for deeper look-ahead (game-engine/hypothetical-resolution-failure#only-holds-may-lag)
- [ ] 5.3 Return a failure on contradictory or structurally impossible input — a direction supplied for a snake also held, a held snake that is not alive, a state whose bodies are non-contiguous or doubly occupied (game-engine/hypothetical-resolution-failure#impossible-input-is-refused)
- [ ] 5.4 Make failures carry enough to act on: which snake, which family of refusal, and no partial state alongside — a caller must not be able to use half an answer (game-engine/hypothetical-resolution-failure)
- [ ] 5.5 Confirm the deliberate non-failures behave as specified rather than being refused: holding every snake returns the state unchanged, which follows from the current turn being the greatest any snake reached rather than needing a special case, and a hypothetical in which a whole team dies reports no outcome rather than a victory (game-engine/hypothetical-resolution-failure#holding-everything-is-a-no-op-not-a-failure, game-engine/turn-resolution-model#spawning-and-outcome-need-lockstep)

## 6. Standing score at any turn (`packages/engine/`)

- [ ] 6.1 Separate the standing score from the final score in the implementation as the delta separates them in prose: one calculation over a state yielding each competing team's normalised body-share score, and a game-end path applying the ending-specific adjustments and the win/draw determination on top (game-engine/scoring, `#standing-score-at-any-turn`)
- [ ] 6.2 Export the standing-score calculation. It is currently unreachable — `checkWinConditions` is internal to the resolver and yields scores only at a terminal turn — and an unexported calculation is indistinguishable from an absent one to every consumer. The consumer is the resolving transaction rather than an observation surface: `game-runtime/per-turn-scoreboard` computes and commits a row per rostered team with the turn it summarises, and the observation capability only delivers what that wrote — so what this change owes is a pure calculation over a state, and nothing shaped like a scoreboard (seam: `mint-game-runtime`) (game-engine/scoring, global-invariants/one-shared-engine#no-parallel-implementation, game-runtime/per-turn-scoreboard)
- [ ] 6.3 Pin the two properties a consumer relies on: every competing team appears with a score on every turn including turn 0, and a forfeited team is excluded from both terms while staying enumerable, so a caller can render one row per rostered team without the forfeiter polluting the denominator (game-engine/scoring#forfeit-exclusion)
- [ ] 6.4 State and test the standing score when no snake is alive, since both terms are then zero — a defined result rather than a division left to chance (game-engine/scoring)

## 9. Time as a declared resolution input, and the endings it makes derivable (`packages/engine/`)

- [ ] 9.1 Add the two timing parameters to both entry points — the turn's clock duration and a per-team burn — as required inputs, and refuse a negative value on the hypothetical path with the other impossible inputs. They are values the caller declares, never values the engine reads: no `Date.now`, no host clock, anywhere in `packages/engine/` (game-engine/turn-resolution-model, game-engine/determinism#time-is-an-input-not-a-reading, game-engine/runtime-portability#no-ambient-nondeterminism, game-engine/hypothetical-resolution-failure#impossible-input-is-refused)
- [ ] 9.2 Move the clock arithmetic from between-turn helpers into the commit stage: spend each team's declared burn from its per-turn clock (clamped to what the clock holds), bank the remainder, apply the next turn's increment and carve-out, and advance the game's consumed duration by the turn's declared duration — one commit, one channel. `initialClock` stays as setup arithmetic; `applyTurnStart` and `declareTurnOver` stop being surfaces a runtime drives between turns, and the `budgetMs + perTurnMs` invariant is asserted across the whole sequence rather than per helper (game-engine/chess-timer, game-engine/chess-timer#only-a-resolution-moves-a-budget, game-engine/chess-timer#carve-out-arithmetic)
- [ ] 9.3 Add the game's consumed wall-clock duration to the state alongside the per-team clocks, and sweep the consumers that assemble the aggregate — `apps/visual-tester/` alone today, per task 1.4. Keep it a total the engine advances, not a timestamp: a total is a function of what was declared to each resolution, which is what makes the duration-limit ending recomputable from the record (game-engine/chess-timer, game-engine/game-end-conditions#the-duration-limit-is-an-ending-like-any-other)
- [ ] 9.4 Gate the clock movements and the duration advance on the state's current turn advancing — a condition on the state, like the spawning gate, and not on which entry point was called. Test the two edges together: a resolution that advances one snake charges every team's declared burn, and a resolution holding every snake charges nothing and returns the state it was given (game-engine/turn-resolution-model#a-turn-nobody-took-charges-nothing, game-engine/held-snakes#a-held-snakes-team-still-spends-its-time, game-engine/hypothetical-resolution-failure#holding-everything-is-a-no-op-not-a-failure)
- [ ] 9.5 Kill the snakes of a competing team left with no remaining time at all, inside the same commit and in the stated order: spend the burn, bank the remainder, kill on exhaustion, **then** apply the next turn's increment and carve-out. Ordering it that way is what makes zero reachable at all when the increment is positive, so test the order directly rather than trusting it, and distinguish exhaustion from ordinary expiry in the test names — a clock reaching zero while the budget still holds time ends the turn only (game-engine/chess-timer#exhaustion-kills-the-teams-snakes, game-engine/chess-timer#the-increment-is-not-a-floor)
- [ ] 9.6 Extend the win check with **one** time-based condition — the consumed duration reaching a positive `maxGameDurationMs` — and confirm the clock needs none: the deaths of 9.5 are committed before the end conditions are evaluated, so a team out of time reaches last-team-standing or simultaneous elimination through the ordinary elimination path. Test the three-team case that must *not* end (one team out of time, two still playing) beside the two-team case that must (game-engine/game-end-conditions#a-team-out-of-time-ends-nothing-by-itself, game-engine/game-end-conditions#the-duration-limit-is-an-ending-like-any-other, game-engine/game-end-conditions#the-first-condition-met-ends-the-game)
- [ ] 9.7 Confirm scoring needs no adjustment for the clock at all: a team whose snakes died to exhaustion scores by the ordinary rules — 0 as an eliminated team where those deaths ended the game, and its plain standing score (0, holding no living segment) while the game runs on — while a duration-limit ending takes every team's plain standing score. Delete any special case reaching for the clock, and test the two adjacently since both read as "time ran out" (game-engine/scoring#running-out-of-time-needs-no-adjustment, game-engine/scoring#the-duration-limit-faults-nobody, game-engine/scoring#ending-specific-scores)
- [ ] 9.8 Emit the exhaustion deaths through the ordinary death event with a new cause, `clock_exhaustion`, alongside `wall` / `self_collision` / `body_collision` / `head_to_head` / `health_depletion` — a new cause in the existing closed set, not a new event kind, and no killer. Confirm the boundary with the causes already reported: a snake killed by a board rule this turn is not alive at that commit and reports its own cause, so one act never produces two deaths (game-engine/turn-events, game-engine/turn-events#every-significant-outcome-is-an-event, game-engine/chess-timer#exhaustion-kills-the-teams-snakes)
- [ ] 9.9 Pin the determinism property the whole design rests on: the same state, directions, seed and timings resolve identically, and two runs differing only in their declared timings differ only where a clock or the consumed duration should make them differ. Include the property over generated timings, not just fixed ones (game-engine/determinism#reproducibility, game-engine/determinism#time-is-an-input-not-a-reading, game-engine/turn-events#deterministic-order)

## 12. Board generation leaves the engine's contract — spec now, code later

The engine takes a **fully specified board**: cells with their terrain, snakes with their team assignments and bodies, the items. The board's dimensions state its size and the placed snakes state the per-team count, so nothing about fertile density, clustering, hazard proportion or snakes-per-team is the engine's to know. The requirements move in this change; `packages/engine/src/boardgen.ts` and `perlin.ts` **stay exactly where they are** and are extracted by a later PR (12.6–12.9 are that PR's plan, not this one's work).

- [ ] 12.1 Confirm the move landed as one operation before anything else in this section: six requirements removed from `game-engine` and re-authored in `game-configuration` by `migrate-game-configuration`'s mint delta, `game-engine/board-geometry` reworded from a construction rule into the validity rule the engine actually applies, and the five generation rows gone from the engine's parameter table. Read the boundary decision that already stands first — generation parameters are consumed platform-side and never reach the runtime, and whether fertile ground is on is derived from the board's cells rather than from configuration: this is packaging catching up with a decision already made and already implemented at the boundary that governs gameplay, not a reversal of it (game-engine/board-geometry, game-engine/configuration-parameters, game-configuration/generation-parameters)
