## 3. Centaur-subsystem pacing records (Convex — `packages/convex-centaur-state/`, `packages/convex-host/`)

Initialisation must supply the automatic submission time allocation's default where the team captured none: exactly the clock time the game accrues to the team each turn, read from the game's own timer configuration rather than any platform constant, with a test at a second budget configuration proving the default tracks the format instead of a hard-coded number (turn-pacing/live-pacing-parameters, turn-pacing/live-pacing-parameters#live-record-not-derivation, turn-pacing/live-pacing-parameters#mid-game-retuning-is-live, turn-pacing/live-pacing-parameters#unset-allocation-defaults-to-the-turns-accrual, game-engine/chess-timer#carve-out-arithmetic)

The captured value must be able to arrive **unset** — `bot-configuration/team-bot-parameters#unset-timing-parameter-stays-unset` stores no placeholder — so the validator and the capture path both carry absence through to this record's initialisation, which is where the default is applied (turn-pacing/live-pacing-parameters#unset-allocation-defaults-to-the-turns-accrual, bot-configuration/game-start-snapshot)

Test that a retune moves both, and that the simulation side snapshots the value at the turn's start rather than mid-turn — the projection and the real deadline must never disagree about how long the turn is (turn-pacing/live-pacing-parameters#live-record-not-derivation, turn-pacing/live-pacing-parameters#mid-game-retuning-is-live, bot-framework/simulated-turn-timings#the-turn-holds-one-allocation)

## 4. Automated player submission pacing (`packages/centaur-server-lib/`)

- [ ] 4.1 Implement the scheduled submission pass on the team's live scheduled-submission interval, sweeping only automatic-mode snakes whose decision state has news: sample, stage, and re-arm the interval when the live parameter changes. **Seams:** the dirty flag's meaning is `bot-framework/score-composition`'s, sampling is `bot-framework/softmax-decision`'s, the staging write is `game-runtime/staged-move-log`'s, and manual-mode exclusion is `operator-control/manual-mode`'s (turn-pacing/scheduled-submission, turn-pacing/scheduled-submission#no-news-no-reroll)
- [ ] 4.2 Make this workflow the sole clearer of a snake's news and bind the clear to the staging acknowledgement — never at sampling, never at send, and never as a side effect of the decision-state publication the same pass performs — so a failed or unacknowledged staging leaves the snake pending and the next pass retries; test the lost-acknowledgement path and the published-but-not-staged path explicitly. **Seam:** setting the flag (and that publication never consumes it) is `bot-framework/score-composition`'s half of the same lifecycle (turn-pacing/scheduled-submission#ack-gates-the-clear, turn-pacing/scheduled-submission#publishing-is-not-staging)
- [ ] 4.3 Arm the per-turn final-submission deadline from live state — the smaller of the automatic allocation and the observed remaining time, brought forward by the imminent threshold — and re-arm it earlier whenever observed remaining time falls below what the armed deadline assumed, with a test driving a mid-turn shrink (turn-pacing/final-flush, turn-pacing/final-flush#deadline-tracks-the-clock, turn-pacing/final-flush#expiry-never-wastes-decisions)
- [ ] 4.4 Implement the deadline behaviour: flush every automatic-mode snake with pending news however recently staged, then declare the turn over when the flow quorum permits — immediately if it holds at the deadline, otherwise on the player's own schedule later in the turn — while the scheduled cadence keeps running until the turn is actually declared over; the withheld-quorum case flushes but defers declaration (turn-pacing/final-flush#quorum-withheld-flushes-but-defers, turn-pacing/flow-quorum#passive-never-a-trigger)
- [ ] 4.5 Make declaration coordination observation-only: the player learns of *any* declaration — the Captain's submit included — solely from the declared state on its own game subscription, cancels its pending flush from that observation, and exposes no interface-to-player channel. **Seam:** the filtered subscription delivering declared state is `live-game-observation`'s; the boundary forbidding any other channel is `global-invariants/centaur-state-boundary#bot-to-game-flow-never-routes-through-convex` (turn-pacing/captain-submit#declaration-observed-never-signalled, turn-pacing/captain-submit#no-flush-after-the-human-decision)

## 5. Captain controls and the pacing header (`apps/centaur-server-reference/`)

- [ ] 5.1 Implement the Captain's immediate turn-submit — declaring the team's turn over at once with exactly the moves currently staged, tempo-blind, offered to the current Captain alone, additionally bound to a keyboard shortcut usable without pointer input. Write **no** server-side non-Captain gate on the submission path: the Captain-only allocation is this application's presentation choice, not an access control, and a fork that offers the affordance more widely is behaving correctly. Note the boot affordance rendered alongside it is `operator-control/captain-boot`'s behaviour, mirrored here only as header placement (turn-pacing/captain-submit, turn-pacing/captain-submit#immediate-and-tempo-blind, turn-pacing/captain-submit#keyboard-under-pressure, turn-pacing/captain-submit#captain-only-is-allocation-not-enforcement)
- [ ] 5.2 Build the pacing header: current turn number, the team's clock countdown at sub-second precision with a distinct warning state as expiry nears, remaining budget, and each active operator's tempo on the presence display — reading tempo from the durable record and never inferring it from presence, which proves connectedness only. **Seams:** the presence display, operator colour, and the client-measured latency indicator are `operator-control/operator-presence-and-identity`'s (turn-pacing/pacing-header, turn-pacing/pacing-header#sub-second-countdown-with-warning, turn-pacing/pacing-header#tempo-from-the-record)
- [ ] 5.3 Replace the countdown with a stable turn-submitted indicator once the team has declared, holding steady while the remaining teams finish declaring and never flickering back to a countdown before the next turn opens — including across authoritative-update gaps if the countdown interpolates locally between them (turn-pacing/pacing-header#submitted-indicator-holds)
- [ ] 5.4 Expose the operator's own tempo toggle in the header — every member operator's own control, never the Captain's to set on their behalf, durable across turns in the display as in the record, and available in either tempo without affecting any other interaction (turn-pacing/operator-tempo, turn-pacing/operator-tempo#durable-across-turns)
