# Agent Context — packages/convex-host

This package is `@cyphid/snek-convex-host`: the Convex app (the single persistent deployment) that mounts the Convex Components and provides the full deployed backend — including the platform's identity, credential-issuance, and authorization surface.

## Spec scope

- **`identity-and-authorization`** (open change `migrate-identity-and-authorization`) — human sign-in, the trusted-issuer registry, the assertion exchange, the sign-in handoff, the capability registry and kind gating, and every credential the platform mints. Implemented here; see "Auth integration" below.
- **`game-configuration`** (open change `migrate-game-configuration`) — the public game-configuration function surface. Implemented as thin pass-throughs, now wrapped by the capability registry.
- **Module 05** (`legacy-spec-archive/spec/05-convex-platform.md`) — integration surface, game lifecycle (delegated to component).
- **Module 06** (`legacy-spec-archive/spec/06-centaur-state.md`) — Centaur state mutations (delegated to component).

## Layout

| Path | What it is |

| `convex/convex.config.ts` | `defineApp()` mounting `@cyphid/convex-snek-platform/convex.config` **and** the local-install Better Auth component (`./betterAuth/convex.config`). (`convex-centaur-state` is still a stub and mounts when its stories land.) |

## Toolchain

- `pnpm codegen` — the offline codegen recipe (no Convex account needed): `CONVEX_SELF_HOSTED_URL=http://127.0.0.1:6790 CONVEX_SELF_HOSTED_ADMIN_KEY=fake convex codegen --typecheck disable || true`. It writes `convex/_generated` **and** each mounted component's `_generated` (the Better Auth component's included), then fails at a network step — the `|| true` is expected. Commit the output. The generated `api.d.ts` is the untyped AnyApi stub (fine — modules type component references by hand behind small facade interfaces); `dataModel.d.ts` is fully typed from schema.
- `pnpm test` — vitest, `environment: "edge-runtime"`, `server.deps.inline: ["convex-test", "@convex-dev/better-auth"]` (both must run inside the simulated isolate); module globs must include `_generated`.

## Auth integration (IMPLEMENTED)

### Where Better Auth lives

Locally installed: the component is embedded at `convex/betterAuth/` and mounted by `convex/convex.config.ts`, so its schema is modifiable where it lives. `convex/auth.ts` builds the instance from `better-auth/minimal` plus the `@convex-dev/better-auth` client (`authComponent`, created with `{ local: { schema } }`). The library supplies key management, signing, publication of verification material, and human authentication — nothing else. Forking the integration remains rejected.

### The protocol/policy split as shipped

**Protocol** (the mechanics of exchanging and minting credentials):

- `convex/lib/issuance.ts` — assertion verification against a registered principal's *published* material (jose against the registration's `materialUrl`, with a per-URL cache and a refetch-on-unknown-key path so key rotation needs no coordination), plus the transactional single-use `acceptJti` mutation.
- `convex/lib/handoff.ts` — the transactional halves of the sign-in handoff: `createReference` (return address strictly from the registration) and `redeemReference` (single-use flip + verifier comparison in one serializable transaction).
- `convex/lib/signing.ts` — minting platform-signed credentials (below).
- `convex/lib/sha256.ts`, `convex/lib/sessionLifetime.ts` — hashing and the session-lifetime configuration.

**Policy** (the authorization rules, in ordinary application code — never inside the auth layer):

- `convex/lib/registry.ts` — the capability registry and kind gating. **Every public function is built through `platformQuery` / `platformMutation` / `platformAction` / `platformHttpAction`** — never the raw constructors. The wrapper resolves the caller to a closed `ResolvedCaller` union (human / centaur-team / external-system, decided structurally from the credential's claims), checks the declared capability first (reachability), the declared principal kinds second (humans-only is the default), and hands the handler the resolved caller for its own authorization decision. `tests/registry-totality.test.ts` makes the declaration total at build time: any public function without registration metadata, or any raw constructor call outside `lib/` and `betterAuth/`, fails `pnpm test` and with it the build gate.
- `convex/lib/grants.ts` — what each principal's credential is minted with (the only place a capability set is assembled).
- `convex/schema.ts` — the issuer registry with its ceilings, return addresses, and rate bounds.
- The game-credential issuance *policy* (game playing, team registered, registration is the team's own, ceiling excess named) lives in `convex/http.ts` beside the endpoint.

The shared vocabulary — capability entries and claim names, game-subject encoding, audiences — is `@cyphid/snek-platform-auth`, read by every runtime that mints or admits.

### Exactly how tokens are signed

One signing arrangement behind every credential; containment comes from audience binding, not separated key material.

- **The key**: a single Ed25519 (EdDSA) key pair that Better Auth manages in the **local-install component's `jwks` table** (`convex/betterAuth/schema.ts`) — public key published in the served JWKS, **private key stored encrypted under `BETTER_AUTH_SECRET`** in that same row. It is created on first use and decrypted only inside a Convex action; it never leaves the deployment.
- **Human working JWTs** are signed by the Better Auth convex plugin itself (the `/api/auth/convex/token` route), 15 minutes, capabilities minted via `definePayload` in `convex/auth.ts`.
- **Game credentials and game access tokens** are minted by `mintPlatformCredential` in `convex/lib/signing.ts`: it calls Better Auth's exported `signJWT` (`better-auth/plugins/jwt`) against the resolved auth context, with mirrored jwks adapter overrides (the component adapter stores `createdAt` as a number; the jwt plugin expects Dates) so a directly-invoked `signJWT` reads and creates keys identically to the plugin. Issuer is `CONVEX_SITE_URL`; expiry is pinned to `WORKING_CREDENTIAL_LIFETIME_SECONDS` (15 minutes) and nothing a caller passes can lengthen it.
- **Verification** is against the JWKS served at `/api/auth/convex/jwks` — one platform-wide published document covers every credential (working JWTs, game credentials, game access tokens alike).

### Session lifetime

A deployment configuration (`SESSION_LIFETIME_SECONDS`), defaulting to seven days, **floored at four hours in code**: `sessionLifetimeSeconds()` throws at auth construction on a lifetime below the floor (never clamps). The session is the one stateful credential permitted to outlive the fifteen-minute bound; working-credential renewal re-reads it on every `/token` call, so revoking the session ends renewal instantly.

### How tests authenticate (tests/setup.ts)

Google OAuth is **config-only offline** — no test completes a Google round trip. The patterns:

- `setup()` builds the convex-test harness with the host schema/modules and registers **both** components: `snek-platform` and `betterAuth` (module globs must reach `_generated`). Call `setAuthEnv()` in `beforeAll` (sets `BETTER_AUTH_SECRET`, `SITE_URL`, `CONVEX_SITE_URL`, Google stand-ins).
- **Humans**: `makeHuman(t)` creates a Better Auth user row through `convex/lib/testSupport.ts` internal mutations (the stand-in for a completed sign-in) and returns a `withIdentity` claim set shaped like a working JWT — `subject` = user id plus the structured `cyphid.capabilities` claim. Function-level tests then run as `t.withIdentity(identity)`.
- **Sessions / HTTP**: `testSupport.createSession` inserts a session row; HTTP routes are exercised with `t.fetch(...)` and `authorization: Bearer <session token>` (the convex plugin bundles bearer transport). `testSupport.revokeSession` is the kill switch for renewal tests.
- **Service principals**: `gameCredentialIdentity(teamId, gameId)` fabricates a per-team game-credential claim set for function-level tests; the full assertion exchange (real Ed25519 keys, material served via `__setMaterialFetchForTests`, registration rows inserted with `t.run`) is exercised end-to-end in `tests/issuance.test.ts`.
- **Game scaffolding**: `launchGameAs` runs create→roster→launch; `testSupport.setRosterSnapshot` / `finishGame` stand in for the lifecycle story's orchestration.
- `tests/tokens.test.ts` closes the loop across runtimes: tokens minted here are verified with jose against the served JWKS and fed to `@cyphid/snek-stdb`'s `decideAdmission` — mint-to-admit coherence.
